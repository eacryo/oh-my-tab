# 审查积压（Review backlog）

在 *Review budget and triage*（AGENTS.md）下判定为有效但超出范围的发现，以及没有任何一轮关闭的已知缺口。这里没有任何一条是在声称行为正确——每条都是一次决定：把这项工作排期，而不是在暴露它的那次改动里顺手做掉。

在一轮被分诊时就补记，不要拖后：轮次、严重度、为何延后，以及把它带回来的触发条件。它的工作落地后删掉该条，并在提交或发布说明里讲明。

**关于下文的历史层级用语（2026-10-29 补记的换算说明，不改写任何历史条目）。** 下文按写作时的分层术语（`A1`／`A2`／`tier-B`／`A 层`）记录当时的结论；那套分层已被设计评审商定的两维分类取代（`docs/architecture-test-remediation-plan.md` 顶部的状态声明给出了完整口径）。读旧条目时按此换算：

- 旧的“A1”（smoke runner／纯无头测试，代码判定）→ 按**是否打扰**拆开：headless 测试与经证实不启动 app、不抓屏、不注入输入也不重启实例的 smoke runner 属 **M1**（日常门禁）；会启动真实 AppKit 视图树的 GUI smoke runner 属 **M2**。旧条目里“A1 断言”读作“M 类断言”即可，判定权本来就在代码。
- 旧的“A2”（e2e 场景）→ **M2**：代码判定、会打扰。旧条目里的 `--include-focus`／`--include-screen`／`--include-prefs` 及退出码 75 的记录照旧有效。
- 旧的“tier-B 证据”／“人工实机验证”／“agent 或人判定” → **A 类**，且 A 类永远不是门禁证据：agent 读状态或**已存在**的截图文件是 **A1**，必须实时观看（实时 UI 审查、e2e 运行分诊）是 **A2**。
- 晋升规则不变、只是换词：agent 审查发现的回归必须落成一条 **M 类断言**，或新增一个使之可断言的状态字段。

注意旧术语“A1／A2”与新格子的“A1／A2”同名而含义不同：旧 `A1/A2` 是代码判定的门禁层，新 `A1/A2` 是 agent 判定的非门禁格子。因此本文件的历史条目**不逐条改写**，需要新读法时看这张表。
