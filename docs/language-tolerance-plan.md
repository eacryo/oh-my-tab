# 语言容忍度落地计划（Language Tolerance Plan）

本计划说明如何把 `docs/design-style.md` §11 的语言容忍度规则（连同 §4、§9 的相关条款）落到代码与验收里。

**本文是计划，不是规范。** 规范本体是 `docs/design-style.md`；两者冲突时以规范为准。本计划的规则来源是
Rene Wang 的 [Build Interfaces That Survive Translation](https://rene.wang/essay/build-interfaces-that-survive-translation)
以及为落地它而做的四轮审查。

静态勘查锚定提交 `35d6073`。引用行号会随后续改动漂移；需要长期维护的是 **LT-1 的登记表**与
**LT-2 的断言**，不是行号。

修订记录：v1 初稿；v2 采纳第一、二轮审查；v3 折入 §9 的 R1–R5 与作者核对（§10）；v4 折入 §11 的五条
补充与作者核对（§12）；**v5 折入 §13 的五条补充与作者核对（§14）**。§9、§11、§13 是外部评审原文，
§10、§12、§14 是作者回应；正文以最新一轮为准。

## 1. 方法

四条工作规则，由本计划前两稿被推翻的假设换来：

1. **不用静态命中数代表覆盖。** 某个 API 的命中数不等于截断清单；截断机制至少五类（见 LT-1）。
2. **不用估算常量代表渲染结果。** `DETAIL_LINE_H` 的注释自述它是「防止实际行盒超过估算」的上限值，不能
   据此反推实际行高。
3. **不用单语言或人造字符串代表各语言。** `[TEST] English x3` 是空格连接的英文重复，不模拟 CJK 无空格
   的行为，不能当宽度上界；但规范 §11.1 的长文本存活要求仍然成立，两者是不同的问题。
4. **以可见内容与表面为登记单位**，不以 API 调用次数推算站点数；调用点集合的静态检查只用来发现机制变动，
   而且必须先定义「调用点 → 内容站点」的映射才能判定（见 LT-1 登记规则）。

分层原则：**凡可断言的都进 A 层**（`AGENTS.md`：严重性不是分界，可断言性才是）。A 层做不到的（断词质量、
镜像观感）走 B 层；暂时无法断言的记为**未验证**，不得以 B 层目测充当完成。发现缺陷后按 promotion rule 补
A 层断言或使其可断言的状态字段。

**登记规则（使「调用点 ⊆ 登记表」可判定）**

1. **稳定标识**：`LT1-<类><两位序号>`；同一逻辑项按表面／入口拆开时加小写后缀（`A07a`／`A07b`／`A07c`），
   基号相同即同组。一经分配不得复用或重编号。
2. **登记单位是「内容 + 表面」，不是控件也不是调用点。** 同一控件、甚至同一调用点，可以按**内容状态**
   拆成多项：浮窗页脚的截断调用 `overlay.rs:1396` 同时承载 LT1-A15（`overlay.no_windows`）与
   LT1-C04（窗口标题／应用名回退）。
3. **映射的单位是 `(调用点, 内容状态)`。** 每个 `(调用点, 内容状态)` 对映射到恰好一个登记项；只有完全
   不渲染文本的调用点才进 `no-text` 桶。子集断言 = 代码的 `(调用点 × 内容状态)` 集合 ⊆
   （已登记项 ∪ `no-text`）。**内容状态无法完全静态推导**，因此映射表是人工维护的显式数据（登记表的一部分），
   由断言检查其覆盖性；只靠源码位置不足以判定——这正是 v4 规则「每个调用点恰好对应一个登记项」与
   「同一页脚拆成两项」互相矛盾的原因。
4. **测量与显示是调用性质，不是并列的桶。** 同一登记项可以同时有 `kind=measurement` 与 `kind=display`
   的调用点（例：`setMaximumNumberOfLines` 的临时测量与最终显示）；两者归同一登记项，既不拆成两项，也不
   塞进独立桶。
5. **未知项必须可关闭，且要覆盖两类裁切。** S01 要关闭的是固定帧内**全部**潜在裁切，不只是「可换行且
   未登记」的控件：**单行固定帧文本即使没有显式截断设置也可能溢出**——默认换行会把第一行之后的内容无声丢掉
   （同类说明见 `clipboard/text_style.rs:1228`–`1234`）。关闭判据是——在覆盖清单列出的页面、弹窗与状态
   **全部被实例化之后**遍历视图树，对每个文本控件用不受上限约束的测量（LT-2 方法 4）断言**完整文本能放进
   帧内**；放不下的必须归入某个登记项（含其类别与出口）或修复。**一次遍历只覆盖当时已实例化的控件**，
   所以清单必须显式列出被实例化的表面与触发方式（见 LT-2 的覆盖清单）；未关闭前 LT-1 不算完成。

**改动**
1. 登记表与 `(调用点, 内容状态)` 映射表落地到代码（常量或测试数据），并实现上文的子集断言。
2. A 类逐点处置：加宽列 / 缩短文案 / 提高行数上限。**静默裁切风险项优先做失败可见化**（补省略号），
   再用真实 locale 字符串、最窄宽度与长文本 fixture 证实是否已经溢出；证实前只称「风险」。
3. B 类补齐出口；C 类待 LT-2 的无障碍与完整值取证后再定（§7 决策 3）；D 类修字素簇切分：**D01** 菜单标题
   前缀、**D02** 首字占位图标，两处都要改成按字素簇取用。仓库既无字素簇工具也无相关依赖，可用平台手段
   （`NSString` 的 composed character sequence 枚举，如 `rangeOfComposedCharacterSequenceAtIndex:` 或
   `NSStringEnumerationByComposedCharacterSequences`，实施时确认），并加断言覆盖组合字符与多码点 emoji。
4. 每个 A 类站点在 LT-2 中对应到具体 runner；A07b 需要新建 **fixture**，直接按四个阶段构造更新弹窗
   （`--test-update-notice` 只走「通知 → 设置页 About」路径，不能作为该弹窗的入口）。

**验收（分类）**：A 类——在**原处**读全，由真实布局断言证明；B 类——出口可验证；C 类——按 LT-2 的两条
路径结案；D 类——字素簇断言通过；S01——扫描关闭（**需图形会话**）。另有映射表与代码的覆盖性断言
（纯 headless）。
**风险**：A 类「放不下」的处置需要产品／文案拍板（§7 决策 5）；内容状态映射靠人工维护，漏一项等于漏一个
站点，且子集断言在映射不完整时会给出虚假的通过。

**改动**
1. **可断言的瞬时表面不得降为仅 B 层。** 浮窗与按键显示的文字容纳、裁切、完整值可达性与无障碍属性，
   凡可由脚本观察的，都要补确定性 fixture 与 A 层断言（必要时加可断言的状态字段）；暂时做不到的标
   「未验证」。各入口目前只证明能进入该表面，不构成断言。
2. **无障碍取证是新增能力。** 仓库没有任何无障碍树查询代码（`NSAccessibility` / `accessibilityValue`
   全为空），需要在两种卡片布局（图标卡片、缩略图卡片）下取样：卡片点击目标是否可访问、子文本是否暴露
   完整原文、VoiceOver 能否读到、焦点能否到达。**「没有显式 `setAccessibilityLabel`」不能推出「没有
   无障碍出口」**——浮窗标题是标准 `NSTextField`，可能自带角色与值。
3. 每个相关表面分别检查 `en`、`zh-Hans`、`zh-Hant`；`--pseudo-locale` 与长文本 fixture 作为**独立**压力
   用例（它们是 §11.1 的存活要求，不是 CJK 宽度上界）。可变宽容器至少测正常宽度与最窄可用宽度。
4. **测量方法**：不得用带 `maximumNumberOfLines` 的控件自身的 `sizeThatFits` 判断是否截断——行数上限
   本身会影响返回值。改用不受上限约束的同字体／同段落测量，或检查布局后末尾字形确实可见，并验证文本未与
   邻近控件重叠。断言失败时输出 locale、语义角色、容器宽度与实际所需尺寸。
5. 执行环境见 LT-6 D7：纯 headless 环境不得把未运行的 GUI smoke 记为通过。

### LT-3 · 行高：先定义，再测量，后实施（已收窄必改范围）

**依据**：§4（:171）、§11.4（:452）、现状表的 §11.5 局部结论。
**现状**：此前 `NSTextFieldCell.setDefaultParagraphStyle:` 的实例 selector 不存在，cell 路径静默 no-op；此前 TextKit
smoke 手工构造 attributed string，没有经过该 setter。现在 setter 改为给 `NSTextField.attributedStringValue` 写入段落属性，
并由实际 TextKit line fragment smoke 验证；剪贴板详情与页面标题等 attributed-string 路径也已实际设置行高。
`DETAIL_LINE_H = 18.0`（`src/clipboard.rs:144`）自述为估算上限；引导正文目标为 14pt × 1.4 = 19.6pt。

**第 1 步 · 文档消歧（已完成）**
比例乘字号，目标绝对行高使用 `minimumLineHeight` / `maximumLineHeight`：14pt 正文为 19.6pt，12pt caption
为 16.2pt，标题为字号 × 1.2。只对折行角色生效，不改变单行文本框。

**第 2 步 · 测量**（全部在主线程 smoke 场所）
1. 各角色字体的 `ascender` / `descender` / `leading` → 自然行高；
2. 一段会折行的正文经 `NSLayoutManager` 得到的**实际 line fragment 高度**；
3. 与 §4 目标比较，得出真实差距。

**第 3 步 · 实施（已完成）**
- 只给**会折行**的角色加段落样式（剪贴板列表标题、详情正文与代码、更新说明 markdown、引导页正文与提示、设置页
  多行标签、可折行的按钮标题及页面标题）。单行标签不受影响。
- 行高只影响**纵向**量：同步 `DETAIL_LINE_H` 及其他与纵向尺寸直接相关的布局量，并复核面板裁切与滚动条。
- **`estimate_lines`（`src/clipboard/model.rs:7`）、`detail_text_units`（`:29`）、`LINE_MAX_UNITS`
  （`src/clipboard.rs:152`）估的是横向容纳与行数，行高变化本身不要求修改它们。** 只有真实换行数或面板尺寸
  验证失败时才改，并保留原有的后备估算测试。
- 剪贴板详情的高度后备估算（`src/clipboard/model.rs:7`、`src/clipboard/picker.rs:1576`）不决定实际断点；
  用渲染结果验证它不会造成裁切。

**验收**：TextKit smoke 通过真实 `NSTextField.attributedStringValue` 读取 12pt、14pt 与 26pt 的 line-fragment 高度，
并与字号 × 比例逐项比较；Debug `--smoke-settings-layout` 输出「all pages survived in all locales」。布局 scanner
使用实际 attributed text 的 TextKit 布局检查多行标签完整高度；详情行高后备估算使用同一目标值。优化构建的视觉复核
仍待交接时完成。更新弹窗阶段/按钮的三 locale 检查属于 LT-2 A07b；`--smoke-update-prompts` 会打开 12 个 key window
并抢焦点，须经用户同意后运行，不得把未运行记作通过。LT-3 的代码和 Debug 门禁已通过，视觉复核未完成前不标记关闭。
**风险**：中；改变视觉密度，建议同时在 §4 写明该规则只对折行角色生效。
**依赖**：§7 决策 1（已解决）。

### LT-4 · CJK 词边界断行 spike（限时）

**依据**：§11.2（:410）、§11.7 缺口 3。
**已核实的事实**
- 平台提供 `CFStringTokenizer`（`kCFStringTokenizerUnitWord` / `kCFStringTokenizerUnitWordBoundary`）与
  `NLTokenizer`（`NLTokenUnitWord`）；
- 两层 layout manager 的 delegate 都有软换行判定回调（`NSLayoutManagerDelegate`、
  `NSTextLayoutManagerDelegate`）；
- 我们实际使用 TextKit 1（`clipboard/detail.rs:78`、`clipboard/picker.rs:1682`、`updater.rs:1280`）；
- CoreFoundation 已链接，**NaturalLanguage 尚未链接**。

**范围**：只做一个正文视图（剪贴板详情），不做全量实施。
**检查项**
1. 断点是否真的落在词边界；
2. **选取与复制是否仍正确**——该视图有 source map 与自定义 `copy:`，避让断点可能破坏选区映射，这是本仓库
   特有的风险；
3. 改变宽度后的重排是否正确；
4. 长文本性能——delegate 对**每个候选断点**回调，朴素实现是 O(n²)，需「整串分词一次 + 缓存 + 仅含 CJK 时
   启用」。

**待验证假设（不预先下结论）**：`NSTextField`（设置页、引导页）是否可达——需测试其 cell 布局路径是否经过
可挂 delegate 的 layout manager。
**决策门槛**：若第 4 项无法达标，或第 2 项无法保证，则结论为「不做」，并长期保留 §11.2 的逐宽度实读规则。
**产物**：一页结论（可做／不可做／成本）。

### LT-5 · RTL 定向检查（暂缓）

## 4. 顺序与依赖

```
R1 事实修正（LT-6 D1、D5、D6）
   └─► LT-1（登记表 + 调用点映射 + 稳定标识；含 §11 第 1 条的无障碍取证立项）
            └─► LT-2（逐表面接上断言；浮窗含无障碍取样）
                     └─► LT-3（×字号已决；实施已落，图形验证待完成）
LT-4（独立限时 spike，可与 LT-2 / LT-3 并行）
LT-5（暂缓）
D2–D4、D7（各自随对应工作项一起落地）
```

**完成标准（按类，不是「每个登记项二选一」）**

- **A 类**：在**原处**读全（§9 :325），由真实布局断言证明；不适用出口替代，也不由本计划自行豁免。
- **B 类**：出口可验证（完整原文可取，且出口自身不再截断）。
- **C 类**：两条路径之一——路径 1 出口可验证；路径 2 经产品批准的边界偏离（规范写清表面／内容类型／理由／
  边界 + A 层断言保证不扩散）。
- **D 类**：字素簇切分修复 + 断言通过。**S01**：覆盖清单全部实例化后扫描关闭。

另加：登记表与 `(调用点, 内容状态)` 映射的覆盖性断言通过、每个 A 类站点被相应 runner 覆盖、规范要求的
locale 与压力用例均已实际执行。未批准或未取证的项目不得计入完成。文档、代码与门禁状态在交接时必须一致。

**顺序理由**
1. 先修事实错误（R1）：出口表错会导致后续所有「补出口」的工作做在错的对象上。
2. LT-1 必须先于 LT-2：断言需要登记项作为对象，且调用点映射未定义时子集断言不可判定。
3. LT-3 排在 LT-2 之后：两者都动几何，先让「文本是否放得下」有断言，再改行高。
4. LT-4 独立：不确定性最高，不能阻塞其他项。

## 6. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |

### R3 · 把 LT-2 扩成跨表面的真实验收

1. `--smoke-settings-layout` 负责设置页；设置 tooltip 仍需在该入口中触发并断言。其余 A 类分别接入适合的真实视图入口，例如

   与最窄可用宽度。
3. 测量完整内容时，不只读取带 `maximumNumberOfLines` 的控件当前 `sizeThatFits`：该上限本身会影响返回值。

### R4 · 收窄 LT-3 的必改范围

- 行高单位已定为字号乘比例；图形 smoke 仍需测真实 line fragment。之后继续校准 `DETAIL_LINE_H` 和其他

- `estimate_lines`、`detail_text_units`、`LINE_MAX_UNITS` 估的是横向容纳与行数；**行高变化本身不要求改它们**。
  只有真实换行数或面板尺寸验证失败时才修改，并保留原有后备估算测试。
- 现状表中「§11.5 不信字符数：已满足」改为待复核的局部结论：列表内容不靠字符数截断，但剪贴板详情仍有

## 11. 外部评审对 v3 的补充（2026-10-02）

本节核对 §10 新增判断与 v3 完成标准，不改动作者的核对原文。以下各项在取得所述证据前保持「待验证」。

1. **没有显式无障碍标签，不等于没有无障碍出口。** §2、LT-1 C 类和 §10.2 记录的「overlay 内 0 处
   `setAccessibilityLabel`」是静态事实，但浮窗标题使用标准 AppKit `NSTextField`；标准控件可能自行提供无障碍
   角色和值。应在两种卡片布局下检查实际无障碍树：卡片点击目标是否可访问、子文本是否暴露完整原文、
   VoiceOver 是否能读到，以及焦点能否到达。检查前不能把「没有显式设置」提升为「没有无障碍出口」或预先
   选择记录偏离。即使无障碍树有完整值，也须另行判断视力用户能否到达完整文本；两种出口不能互相代替。
   参考 [Apple 的 AppKit 无障碍说明](https://developer.apple.com/documentation/AppKit/accessibility-for-appkit)。
2. **可断言的瞬时表面不能降为仅 B 层验收。** §7 决策 7 允许「不接 runner，只做 B 层检查」的路径，
   与 `AGENTS.md` 的「Anything assertable belongs in A」及 B 层缺陷 promotion rule 冲突。浮窗与按键显示
   的文字容纳、裁切、完整值和无障碍属性若可由脚本观察，就应补确定性 fixture、A 层断言或使其可断言的
   状态字段。暂时做不到时标为「未验证」，不把 B 层目测记作完成。
3. **统一 LT-1／LT-2 的完成标准与 D1 的偏离路径。** 当前 §4 和 LT-2 要求 B／C 类出口全部可验证，
   D1 却允许在 §9 为某类瞬态数据记录边界明确的偏离。两条路径应分别定义：有出口的，验证完整原文、
   可达路径及出口不再次截断；经产品决策批准偏离的，在规范中写清表面、内容类型、理由和边界，并用
   A 层断言保证偏离没有扩散。未经批准或未验证的项目不得算 LT-1／LT-2 完成。
4. **让登记表符合自己的字段要求。** LT-1 规定每项包含「语义角色／表面／机制／出口／负责的 runner 或
   断言」，但当前 A 类表的五列是「站点／语义角色／表面／机制／出口」，B／C 类列数更少。正式登记表需
   补 runner／断言及稳定站点标识；若还要检查「调用点集合 ⊆ 登记表」，须先定义调用点到内容站点的映射，
   否则源码调用和语义登记无法直接比较。「待发现」项目也不能在完成验收时仍是未知范围。
5. **收紧两处现状判断的措辞。** 浮窗页脚的 `overlay.no_windows` 是本地化的空状态提示，不是 C 类
   「瞬态用户数据」，应单列为必须读全的界面文案。`configure_settings_button_wrapping` 和 `add_tall_row`
   有行数上限且可能无省略号裁切，但 §10.1 尚未给出实际溢出的字符串与布局证据；目前应称「静默裁切
   风险」，用相关 locale、最窄宽度及长文本 fixture 证实是否已经发生。现有 smoke 入口只证明可进入该
   表面，例如 `--smoke-overlay` 当前主要检查唤出路径存活；文字断言仍需新增。

**核查顺序**：先取浮窗的实际无障碍与完整值证据，确定 D1 的产品选项；再给每个登记项补稳定标识和
负责的 A 层断言；最后用各表面的确定性 fixture 核实截断、裁切和偏离边界，再更新 §4、§5 的完成状态。
