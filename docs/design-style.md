# 设计风格（Design Style）

这是 oh-my-tab 所有自绘界面的规范性文档。改动任何用户能看到的东西之前，先读这一份。英文版见
`docs/design-style-en.md`。

以下规则改编自 Meta 的 [Astryx](https://astryx.atmeta.com/docs/principles) 设计系统（语义 token、
每个维度只有一把尺子、按层级划分 surface、有目的的动效），以及本项目已经遵循的 macOS 惯例。当本文
与现有实现冲突时，**以本文为准，现有实现即为缺陷**。

本文 §11 的语言容忍度规则改编自 Rene Wang 的
[Build Interfaces That Survive Translation](https://rene.wang/essay/build-interfaces-that-survive-translation)。

偏离只有两种成立方式，且两种都要留下记录。要么是平台强制——AppKit 自己绘制的控件、系统提供的取值、
用户自己的内容——那就在代码旁写明原因；要么是项目有意放弃某条规则，那就在它适用的章节里写成
**已记录的偏离**，连同边界与理由（目前有两处：§3.3 第 2 条、§11.2）。没有记录的偏离，两种情况都算缺陷。

## 1. 适用范围

| 适用 | 不适用 |
| --- | --- |
| 设置窗口（侧边栏、页面、卡片、行、控件、底部按钮）；本应用生成的菜单项标题与 tooltip 文本 | 我们不绘制的原生 AppKit 外观：红绿灯、菜单排版与系统样式、系统面板 |
| 应用切换浮窗（卡片、标题、选中环、页脚、滚动条、关闭/取消入口） | 原样呈现的用户数据：窗口标题、应用名、剪贴板内容、文件路径 |
| 剪贴板选择器与详情面板 | 第三方窗口缩略图 |
| 引导页、更新提示、通知、tooltip | 未改造的 `NSAlert` / `NSPanel` 系统模板 |
| HUD：按键显示、指针定位、快捷操作反馈 | |

左列全部属于「外观」（chrome），必须使用下文的 token。右列属于「数据」：由布局规则摆放，但内容本身
绝不重新配色或改写。

## 2. 原则

1. **只用语义 token，调用点不写原始值。** 视图请求的是「卡片上的次要文字」，不是 `#73737A`。
2. **每个维度只有一把尺子。** 字号、间距、圆角各有一把固定的短梯子。不在梯子上的取值是 bug，不是特例。
3. **层级来自 surface 和描边，不来自阴影。** elevation 只表达「它浮在别的元素之上」。
4. **动效用来解释变化，绝不拖延操作。** 只做入场/退场，不做 hover 和高频状态。
5. **文字必须可读。** 对比度是量出来的，不是估出来的。
6. **可见即本地化、可见即可读。** 屏幕上不出现内部标识符或配置键；中文本地化界面里不写死英文。用户自己的颜色值只可作为颜色选择器的说明文字显示十六进制。
7. **只在一门语言里成立的规则不是规则。** 每个布局决定都要对照我们发布的所有语言（`en`、`zh-Hans`、`zh-Hant`）
   以及将来可能新增的语言来检查：宽度来自实测，绝不来自数字符（见 §11）。

不得内联十六进制值。

### 3.2 Surface 层级

`window_bg` → `sidebar_bg` → `card_bg` → 弹出面板。每一层与它背后的那层在视觉上可区分，且任何一层不得
承担两种用途。窗口背景上一组成组的行就是一张卡片，不是另一种底色的窗口。

### 3.3 对比度下限

用**合成后**（带 alpha 混合后）的颜色，对元素实际所在的 surface 测量。

**文字**

| 角色 | 下限 | 浅色实测 | 深色实测 |
| --- | --- | --- | --- |
| `text_primary` | 12:1 | 12.97:1（对 `window_bg`） | 15.63:1 |
| `text_secondary` | 7:1 | 8.19:1（对 `window_bg`） | 10.10:1 |
| `text_muted` | 4.5:1 | 5.16:1（对 `window_bg`）、5.53:1（对 `card_bg`） | 6.40:1 / 5.24:1 |
| `link_text` | 4.5:1 | 4.96:1（对 `window_bg`）、5.31:1（对 `card_bg`） | 6.01:1 / 4.92:1 |
| `link_text_hover` | 4.5:1 | 6.34:1（对 `window_bg`）、6.80:1（对 `card_bg`） | 7.28:1 / 5.96:1 |
| `text_disabled` | 2.5:1 | 2.58:1（对 `window_bg`）、2.76:1（对 `card_bg`） | 4.11:1 / 3.37:1 |

浮动面板键帽上的文字另属记录档（主文字 ≥8:1、计数 ≥3.25:1），因为那块表面会随底图移动——见 §9 按键显示。

`text_primary` 是整个调色板余量最小的一个。主文字色或 `window_bg` 变化时必须重测；不要为了「更好看」
而单独把它加深。

侧边栏选中项的标题保持 `accent` 叠在 `selection_bg` 淡色上：蓝色与底色、行的位置、图标 tint 一起标示
选中状态。它是状态文字而非阅读文字——与 `text_disabled` 一样按 2.5:1 而非 4.5:1 要求（在合成后的底色上
实测浅色 2.97:1、深色 3.24:1）。链接色的文字不适用此例外：一律使用 `link_text` / `link_text_hover`。

`scroll_indicator` 本身不承载含义，因此不受文字下限约束；但它必须在两种模式下都位于表面的可见侧：
比浅色面板更深、比深色面板更浅。固定用某一种模式的中性色，在另一种模式下就会消失（黑色滑块对深色
`window_bg` 只有 1.10:1）。

**非文字**

分两条，因为它们回答的是不同的问题。

1. **仅靠颜色承载状态 —— 下限 3:1。** 焦点环、选中环、状态点、错误/警告描边，以及任何「去掉颜色就
   失去含义」的指示。accent 为 `#0A84FF`：对 `card_bg` **3.65:1**，对 `window_bg` 3.40:1。新增状态
   指示必须先实测再上线。
2. **结构性边界 —— 下限 1.2:1，属于记录在案的偏离。** 卡片描边、控件描边、分隔线、开关轨道，
   承载的是填充、形状、位置和标签**已经**表达的信息。它们低于 WCAG 1.4.11 的 3:1 是有意为之：
   在 `card_bg` 上达到 3:1 需要 `rgba(0,0,0,.42)`（即 `#949494`），会像一条又重又不像原生控件的边框。
   实测：`card_border` 对 `card_bg` **1.25:1**；开关关闭态轨道 `#C7C7CC`（浅）**1.68:1**、`#636366`
   （深）**2.33:1**。

   该偏离只在边界**不是控件的唯一标识**时成立。如果一个控件拿掉描边就认不出来——没有填充、没有
   标签、没有形状、旁边也没有图标——那它的描边必须做到 3:1，且应新增一个 `control_border` token，
   而不是去改 `card_border`。

开关是第 2 条的范例：开/关由滑块位置和 accent 填充表达，轨道颜色永远不是唯一信号。

新增 token 必须实测，不许目测。半透明颜色要按合成后的结果算，不能只看 alpha。

### 3.4 半透明

窗口和卡片背景可以半透明，以透出桌面形成玻璃感。设置页侧边栏使用不透明的 `sidebar_bg`，保证颜色稳定。**承载文字的表面必须足够不透明，保证上表在
最差背景下依然成立**。浮窗玻璃是例外：它是覆盖在任意内容之上的临时表面，其文字颜色必须按它能覆盖到的
最深和最浅背景来选。

浮动面板(切换器、剪贴板、按键显示)通过 `panel_material` 设置提供三种材质:

| 材质 | 表面 | 说明 |
| --- | --- | --- |
| `liquid-glass`(默认) | `NSGlassEffectView`,`glass_style`/`glass_tint` 子选项 | macOS < 26 退化为磨砂 |
| `frost` | `NSVisualEffectView`,behind-window,材质跟随主题,另加下述主题表面 wash | 中性系统模糊;玻璃子选项不适用 |
| `opaque` | `window_bg` 填充,无模糊 | 系统开启「减弱透明度」时也是强制回退项 |

材质只改变面板内容背后的表面——文字颜色、间距、圆角与调色板完全遵循本文其余部分。

**承载对比度表的是「文字面」，不是材质。** 面板用两种方式之一满足下限，而这个选择正是三种材质能否互相
区分的分界：

**面板的表面就是它的材质，对比度由「墨」承担。** 没有任何面板在材质之上再画一层文字表面：那种表面只能盖住
面板的一部分，于是在它没盖到的地方就与材质成条（剪贴板面板浅色模式实测：空闲行 `#F3F4F6` 对旁边裸露材质
`#E2E2E4`，差 17 级，看起来像面板被切成条；深色模式约 75 级）。因此文字直接压在材质上，由**墨**守住下限：
半透明表面用动态系统标签色，表面本身就是 `window_bg` 的（`opaque`）用调色板 token。代价写在下面的浮窗档位里，
不藏着。

**材质本身提供模糊；两种外观的差别在 style 与 tint。** 实测方式：高频底图 + 面板覆盖区的高频能量，
与**同一帧内未覆盖的对照格**相除（只有这个基准经得起检验——未覆盖格读回 100% 源图；面板内无材质格 1.000；
普通半透明膜 0.43；`NSVisualEffectView(.hudWindow)` 0.19）：`NSGlassEffectView` 的每一种配置都把该能量压到
0.000–0.003——任何 variant、`regular`/`clear`、玻璃作窗口 contentView 或子视图、设与不设 tint、key 与非 key
面板、同进程与跨进程底图皆然。**因此模糊既不是旋钮，也不是区分维度。** 两种外观是：

| 外观 | `style` | tint |
| --- | --- | --- |
| `regular`（默认） | `.regular`（0） | `glass_tint`，逐字应用 |
| `clear` | `.clear`（1） | 同一 tint；令它更透的是 clear 这个 style |

`glass_tint` 是 `RRGGBBAA`，它的 alpha **就是**强度旋钮（没有单独的不透明度设置）。它作用于**浅色模式**；
深色模式改用固定深色 tint（`#1C1C1E99`）。这个分裂是实测结论而非偏好：面板没有文字表面时墨直接压在玻璃上，
而浅色 tint 在深色模式下让表面停在中灰，那里的 caption 墨最多只有 2.07:1；换成深色 tint 后同一格实测
**黑背景 9.93:1 / 白背景 6.00:1**（`scripts/e2e/panel-contrast.sh`）。两次"更聪明"的尝试都随版本发过，也都错了，记录在此：

- 按模式重新调明度：深色模式变紫——那里的 `palette.window_bg` 近黑，彩页自身的色相成了唯一活下来的东西。
- 把强度又乘了一次 255：alpha 塌成 20%，请求的纱从未真正生效。

默认值是 `eeeeee66`（浅中性色、40%）。除 `clear` 以外的任何值都渲染为 regular 玻璃，因此被下线的外观
（本 App 曾短暂提供名为 `system` 的第三档）会回退，而不会把表面变成空的。`glass_variant`、`--glass-blur`、
`--glass-saturation` 仍是开发开关，发行路径不碰私有 `_variant`——与 alt-tab-macos 的 `.regular` 玻璃同一选择。

**没有任何材质绘制文字底板；每一档按它的表面所能达到的档位验收。**

| 材质 | 它的表面 | 墨 |
| --- | --- | --- |
| `liquid-glass` | 系统玻璃，渲染值远离 `window_bg`（深色模式落在中灰） | 动态系统标签色 |
| `frost` | 磨砂材质（深色模式约 `#868585`） | 动态系统标签色 |
| `opaque` | **就是** `window_bg` | 调色板 token（与它假设的表面完全一致） |

只有 `opaque` 仍适用上面的对比度表。两种半透明表面做不到：材质的色调按定义就偏离 `window_bg`，没有任何
墨色能在其上达到 12:1 / 7:1。它们按下面浮窗那一档验收。

**渲染像素测量，以及它为什么还不是门禁。**手段是 `scripts/e2e/panel-contrast.sh` 与 `scripts/e2e/lib/png_stats.py`：
后者从文件本身推导缩放（固定像素区域在 1 倍屏上会量错条带）、在面板后钉一块纯黑或纯白窗口（让半透明表面有确定的背景）、
并比较两张截图，使**不同的像素就是字形像素**，而不是材质自身的色调噪声（深色磨砂单帧会给出十几个挤在 1.03–1.13:1 的
"墨"，那些是材质）。

审查与合成复现在这套比较里找出三个缺陷，且都会报出错的东西：为抗跨启动抖动而设到 10 个色调单位的差分阈值，会把处于
1.04:1 下限的 caption 整个丢掉、转而把它邻居的 11:1 当成该区域的答案；用**整区平均**当背景，会把 1.17:1 的局部对比度
报成 7.52:1；而只差材质的两个画面会被当成字形，从一个**完全没有文字**的区域里报出 1.26:1 的"墨"。现在测量改用 3 个色调
单位的阈值、对每个连通分量**取其周围像素的局部材质色**、并在差异像素超过区域三分之一时**拒绝**这组图而不是相信它；
三个反例都在 `png_stats.py --selftest` 里（共九例，引用本节任何数字前先跑它）。

**渲染像素实测：同一次启动、每个文字角色一个取景。**`scripts/e2e/panel-contrast.sh` 在面板后钉一块纯黑或纯白窗口（半透明表面的
色调跟随其背后的内容），先拍带文字的面板，再让 app **就地**把面板文字隐藏（`--clipboard-blank-text=after:N`：同一窗口、同一布局、
同一材质），再拍一张，最后测量**两张之间不同的像素**——那些就是字形，而单帧截图无法把它们与材质自身的色调噪声分开。每个取景只含
**一个角色**：筛选行，以及**逐个页脚 caption**；因为把所有 caption 合成一个取景时，其包围盒会把夹在中间的键帽也圈进来（那个并集
量出的"1.12:1"在三种材质上完全相同、连 `opaque` 对照也一样——这就是它不是文字的征兆）。caption 档 3:1，下表为

深色半透明表面上单帧会给出十几个挤在 1.03–1.13:1 的"墨"，于是每个半透明格子都是因**测量**而非**对比度**而失败。
上表数字出自该方法，因此请当作**参考值**：只有当测量直接隔离出字形像素本身（差分截图——两张图里有一张把文字墨设为透明）之后，这一档才真正成为门禁。

**表面即材质的面板，按它自己的档位验收，而不是本表。** 半透明材质的色调远离 `window_bg`（深色模式实测：
液态玻璃 `#6E6E6E`、磨砂 `#868585`，而调色板假设 `#1C1C1E`），在该表面上**没有任何单一墨色**能达到
12:1 / 7:1 下限——中灰表面上的最好结果是 5.71:1。因此这类面板改用动态系统标签色（AppKit 对着实时底图解析
并补偿），并按下面浮窗那一档、以**渲染像素**验收（`text_primary` ≥ 4.5:1、caption ≥ 3:1）。
只有 `opaque`（表面**就是** `window_bg`）仍适用上表。

**浮窗文字自成一档，且它的「墨」是自适应。** 浮窗文字用系统 vibrant 标签色（`NSColor.labelColor` /
`secondaryLabelColor` / `tertiaryLabelColor`）画在材质视图内部，由 AppKit 对着实时底图解析并施加自身的保对比
合成。于是表面可以保持诚实，代价转移到**墨**上——这是这条取舍的第三条出路（另两条是更小的文字面、以及实测
自适应 scrim）。由于颜色归系统所有，浮窗这一档的下限比上表低一级——`text_primary` ≥7:1、
`text_secondary`/`text_muted` ≥4.5:1——且以**渲染像素**在受控底图上验证，绝不用 token 算术。真机实测：中灰桌
面下 vibrant 墨把标题落在 6.57:1、caption 落在 4.67:1，而固定 token 是 6.04:1/2.47:1——小字提升很大，但仍
低于上表，因此单独列档。画在 `window_bg`/`card_bg` 上的一切仍受上表约束。

**半透明表面必须被约束到这个前提下。** 两种模糊材质本身都会漂向中灰：深色模式下实测，纯 frost 落在
`#868585`、liquid glass 落在 `#6E6E6E`，而调色板假定的是 `#1C1C1E`，于是
`text_primary`/`text_secondary`/`text_muted` 从 15.63/10.10/6.40:1 掉到 3.38/2.18/1.38:1 与
4.68/3.03/1.92:1。中灰表面上任何文字色都救不回来——单一颜色在该表面上最高只有 5.71:1，低于本表自身的
12:1 与 7:1 下限——所以被钉住的是**表面**：

- `frost`：在模糊之上用 `window_bg` 按一个能保证最差情况可读的不透明度合成（纯白背景下仍落在灰 51 或更深）。
- `liquid-glass` 的 tint 逐字取自 `glass_tint`（默认 `eeeeee66`，浅中性色、40%），明暗模式一视同仁。
  **不提供面向用户的颜色选择**：它是配置字段，而脱离调色板的色相会让 vibrancy 墨所依据的对比度表失效。

## 4. 文字

只有四档，其余都是 bug。

| 角色 | 字号 | 字重 | 颜色 | 说明 |
| --- | --- | --- | --- | --- |
| `page-title` | 26 | 700 | primary | 设置页标题，每页一个；字距 `-0.4` |
| `sidebar-title` | 20 | 700 | primary | 侧边栏顶部的应用名 |
| `section-header` | 12 | 600 | secondary | 卡片上方的分组标题 |
| `row-label` | 14 | 400 | primary | 设置行标签、列表主文字 |
| `control` | 14 | 400 | primary | 下拉值、输入框文字、按钮标题、行内次要值 |
| `caption` | 12 | 400 | muted | 行说明、版本号、空态、脚注 |

- 内置字重只用 400 / 600 / 700。600 给区块标题，700 给标题。显式配置的 `fonts.*_weight` 是浮窗的高级外观偏好，予以保留；旧版 500 默认值会迁移为 semibold。
- 数字读数（滑杆值、条数、字节数）使用等宽数字（tabular figures），避免切换时抖动。
- 行高按字号相乘：12pt × 1.35 = 16.2pt，14pt × 1.4 = 19.6pt，标题字号 × 1.2。该规则只约束会折行的文本角色；单行文本不因此改变行盒。角色已定义行高时不得手工覆盖。
- 不要靠缩小字号来塞进控件。应该加宽容器或挪走内容（见 §9、§11.2）。
- **12pt 是下限。** 不要为徽标、键帽或密集标签引入更小的字号。汉字的区分特征是**高空间频率的内部笔画**
  （未/末、己/已/巳），能分辨所需的像素高于拉丁字形；对本调色板和这些表面，这条下限就落在 12pt。
- **层级只用字号、字重、颜色。** 绝不让大小写、斜体、小型大写或字距承载含义：中文没有大小写，合成斜体
  只会让密集字形更糟，而字重是这些信号里最弱的一个，因为加粗会把字腔填满，而不是增加与周边空白的对比。
  拉丁设计里想用大小写或斜体的地方，改用颜色和包围。`page-title` 的 `-0.4` 字距是视觉修正而非语义，也是
  全应用唯一允许的字距。
- About 页的版本号是 `caption`，不是一行数据：它属于页面副标题，不该占数值列。

### 4.1 浮窗文字

卡片标题、卡片应用名与页脚是全应用唯一可由用户缩放的文字。两个卡片 caption 共用
`layout.card_text_size`；页脚直接使用独立的 `fonts.status_bar_size` 设置。

| 角色 | 使用 `layout.card_text_size` | 有效字号 |
| --- | --- | --- |
| 卡片标题（`fonts.title_size`） | 是 | 缩放后 13…20pt |
| 卡片应用名（`fonts.app_name_size`） | 是 | 缩放后 13…20pt |
| 页脚（`fonts.status_bar_size`） | 否 | 配置值 13…20pt |

- **卡片 caption 共用一个倍率。** 改动 `layout.card_text_size` 时标题和应用名同步缩放，相对大小不得漂移。
- **钳制作用于缩放后的结果。** 卡片 caption 的 `fonts.*_size` 是基数而非最终字号：以 12pt 为基数时
  卡片标题落在 `card_text_size` 上；应用名按比例缩放，两者都钳在 13…20pt。
- **页脚独立。** 字号直接使用 `fonts.status_bar_size`，经 13…20pt 配置范围校验；不随卡片 caption 缩放。
- **任一 caption 行的行高不超过所在卡片高度的 1/3。**
- **caption 只有一行。** 放不下就省略号截断，绝不换行，也绝不把缩略图挤出卡片。

Markdown 更新说明的一级标题使用 `sidebar-title` 粗体，二级标题使用 `control` semibold。浮窗基数字号、共享倍率和结果钳制已在 `theme.rs` 实现；显式字重覆盖仍视为用户偏好。

## 5. 间距

基准 **4px**。允许的步进：`4 8 12 16 24 32`。2px 仅允许出现在控件**内部**几何（滑块内缩、发丝线偏移），
不得用于同级元素之间。

设置窗口的具名布局度量（全部落在网格上）：

| 度量 | 取值 | 位置 |
| --- | --- | --- |
| 侧边栏宽度 | 220 | `SETTINGS_SIDEBAR_WIDTH` |
| 侧边栏条目内缩 | 12 | `settings/sidebar.rs`（`btn_w = card_w - 24`） |
| 页面顶部留白 | 48 | `SettingsPageHeader::TOP_PADDING` |
| 页面底部留白 | 72 | `SettingsPageHeader::BOTTOM_PADDING` |
| 区块标题上方间距 | 24 | `SETTINGS_SECTION_HEADER_GAP` |
| 标题 → 卡片间距 | 4 | `SETTINGS_SECTION_CARD_GAP` |
| 行间距 | 8 | `SettingsLayout::row_gap` |
| 行高 52，控件高 32，垂直居中 | | `SettingsLayout` |
| 控件列 | 宽 200，右对齐，距卡片右边 16 | `SettingsLayout` |
| 卡片左右内边距 | 16 | 行构造函数（`label_x`、`SETTINGS_CONTROL_TRAILING_INSET`） |

同一种间距绝不允许一会儿 12 一会儿 14。

## 6. 圆角

| Token | 取值 | 用于 |
| --- | --- | --- |
| `radius-control` | 8 | 按钮、输入框、下拉框、色块、列表项高亮、开关轨道的内部几何 |
| `radius-legend-chip` | 5 | 只读快捷键图例中按键符号背后的底色块 |
| `radius-card` | 12 | 卡片、成组行容器、列表块、弹出项 |
| `radius-panel` | 16 | tooltip、下拉面板、HUD、通知卡片 |
| `radius-full` | 9999 | 胶囊：徽标、状态点、开关、滚动条滑块 |
| 窗口圆角 | 由平台决定（实测，当前为 26） | 设置窗口本身 |

**同心规则。** 有内边距的圆角容器，其内部元素的圆角为 `max(0, 外圆角 - 内边距)`。围绕卡片绘制的选中环
半径为 `卡片圆角 + 环内缩`，从而与卡片保持平行；绝不手工指定环半径。
切换器选中环的 `ring_inset` 为 3pt。

小尺寸色块的圆角由自身高度推导，而不是套用 `radius-control`：`radius-control` 是按 32pt 控件设计的，
用在 19pt 色块上会占掉 42% 的高度，形状变成**胶囊**而不是「柔化过的矩形」。`radius-legend-chip`（5pt）
是 19pt 的 26%。`radius-full` 同样不适用于色块——胶囊是另一种形状，不是更圆的矩形。

## 6.1 图例不是控件

**图例**说明「按哪个键做什么」（`↵ 输入选中条目`）；**控件**是用户去操作的东西。两者刻意画得不一样，
这个差异不是装饰：

| | 图例 | 控件 |
| --- | --- | --- |
| 描边 | **无** | 1pt `card_border` |
| 底色 | 比 `field_bg` 更淡的一层浅色 | `field_bg` / `button_bg` |
| 指针状态 | 无 | hover、pressed、focus、disabled（§10） |
| 命中区域 | 无——它不可点 | ≥ 28×28 |

剪贴板底部的快捷键符号就是催生本节的情况。它们完全没有 target/action，但一次设计系统改造给它们加上了
`field_bg` **加 1pt 描边**——正是可点击控件的视觉契约。这是 UI 兑现不了的承诺：用户会学到「有描边的色块
可以点」，然后发现这些点不动。这套 accent 键帽色板（`keycap_accent_*`）在这里同样不适用——它的含义是
「该修饰键当前正被按下」，那是一个**实时状态**，而实时状态属于按键显示面板。

所以图例只保留「能被读懂」所需的东西：一层淡到不暗示交互的底色，它唯一的作用是把符号和它的说明绑定在
一起，让一行的多个图例仍然可扫读。它**不能**借用控件的描边、圆角阶或指针状态。

「尽可能淡」有下界，不能随意：底色必须仍然能与它所在的表面区分开，且在明暗两种模式下都成立。它以
wash 的方式施加（在浅色表面上压暗、在深色表面上提亮），而不是固定灰，因此一个取值在两种模式下都可用。

浮窗卡片圆角跟随 `appearance.corner_radius`，但最大为 `radius-panel`（16pt）。更大的配置值仍用于玻璃和窗口表面，
不会让切换器卡片变得过圆。窗口缩略图本身保持直角；关闭按钮和选中环从有效卡片半径派生，避免设置变化后残留过期几何。标题栏中的小应用图标使用 `radius-control`。

## 7. Elevation

四档。按**表面离页面多远**选，而不是按「阴影多重才好看」选。

| 档位 | 阴影 | 用途 |
| --- | --- | --- |
| `none` | —（仅描边） | 默认。行、卡片、行内提示、按钮 |
| `low` | `0 1px 2px rgba(0,0,0,.06)` | 需要与背景区分、但仍在文档流内的表面 |
| `med` | `0 4px 12px rgba(0,0,0,.10)` + 描边 | 浮在页面内容之上：popover、下拉菜单、tooltip |
| `high` | `0 12px 32px rgba(0,0,0,.18)` | 浮在整个界面之上：对话框、引导页、带遮罩的浮窗面板 |

中档 elevation 在 `theme.rs` 中由一组共享的黑色阴影、不透明度、模糊半径和垂直偏移表示；下拉菜单和 tooltip
共用这些常量。缩略图角标（全屏、最小化/隐藏）是承载白色符号的圆形 `badge_scrim` 圆片；圆片使用单独命名的
`symbol_shadow` 角色和共享几何常量；它是小尺寸对比辅助，不是表面 elevation。
该阴影的不透明度为 0.85、模糊半径为 2pt、垂直偏移为 −1pt。白色符号叠在纯白缩略图上的圆片之上实测对比度为
4.74:1，高于非文字指示器 3:1 的下限。

- 每个表面只用一档，绝不叠加阴影来「更浮」。
- 设置页里的卡片是 `none`：层级来自 `card_bg` + `card_border`。窗口内的卡片挂一层大范围柔光就是 bug，
  它暗示卡片浮在某个它并没有浮在之上的东西上面。
- 描边用 `card_border`，不要用阴影代替，也不要用更深的底色代替。
- 输入焦点使用内嵌 accent 环（2pt，见 §10），它不属于 elevation。卡片或缩略图块的选中态可以使用外侧 accent
  环；其外侧圆角按 §6 由卡片圆角和环内缩推导。

## 8. 动效

| Token | 取值 | 用途 |
| --- | --- | --- |
| `duration-fast` | 175 ms | 微交互；开关按压反馈使用组件专属时长 |
| `duration-medium` | 380 ms | 空间变化：面板开合、展开/收起、页面切换 |
| `ease-standard` | `cubic-bezier(0.24, 1, 0.4, 1)` | 除有明确理由外，所有动画 |
| 退场时长 | 入场时长的 0.75 倍，曲线相同 | 关闭面板、关闭对话框 |

规则：

- **上下文 UI 只做入场动画。** tooltip、hover 卡片、下拉菜单可以瞬间消失；面板、对话框、展开的行两个
  方向都做动画，且退场沿入场方向原路返回。
- **绝不动画化**：hover 填充、行高亮、用户连续移动中的选中、滚动，以及任何一分钟会触发多次的交互。
  这些必须瞬间完成。
- 动画不得阻塞输入：已经在动画的内容，只要可交互就保持可交互。
- 弹簧仅用于「物理手感本身就是目的」的地方（开关滑块、卡片关闭、面板回弹）。每个组件只用一条既定弹簧；
  不得在每个调用点微调 stiffness/damping；同一种手势在不同组件里不得用不同弹簧。
- **Reduce Motion 是强制的，且在动画发生时读取**，不能在启动时缓存：
  `NSWorkspace.accessibilityDisplayShouldReduceMotion` 为真时改为瞬时切换。所有动画表面都要处理，
  包括浮窗、页面切换和设置窗口外壳。

## 9. 组件

**设置行。** 左侧标签（14 / primary），右侧控件，右对齐到控件列。标签下可有一行可选 `caption`（12 / muted）。
一行一个概念。

- 控件高度恒为 32（单行）。放不下的值用省略号截断，并在 tooltip 里给出完整值——**控件绝不折成两行**。
- 行标签是名词短语，不是句子。解释性内容放到 caption 行。
- **行标签必须在每个已发布的 locale 里完整可读。** 标签放不下时，截断不是修法：加宽标签列、缩短字符串，
  或把细节移到 caption 行——绝不缩小字号（见 §4）。
- **截断有允许清单。** 默认只有以下内容可以截断：控件的值（下拉、输入框、只读值）、`caption`，以及用户数据
  （窗口标题、应用名、剪贴板内容）。控件值须由 tooltip 提供完整值；被截断的 `caption` 须能从关联的完整文本
  表面读到；用户数据须有键盘与 VoiceOver 可达、且自身不再截断的完整内容出口。不能假定某个无关面板或切换
  窗口后自然可见就是出口。标签、区块标题、按钮标题、权限状态和错误原因必须在原处放得下；tooltip 不豁免。
  放不下就改写或调整布局（见 §11.2）。
- **不要用一个词去补一个有歧义的设计。** 如果两个操作要靠「仅」「只」「也」才能区分，那是分组或顺序错了：
  把它们分开，或把次要操作挪远。解释性文字属于 caption 行或无障碍标签，绝不做「让控件不再有歧义」的
  那件东西。
- 行之间用卡片内通栏的 1px `separator` 分隔；首行和末行在卡片边缘处没有分隔线。

**卡片。** 用于成组的行。`radius-card` + `card_bg` + `card_border`，elevation `none`。一张卡片上方配一个
区块标题。如果某一行属于相邻分组，就不要为它单独包一张卡片。

**区块标题。** 12 / 600 / secondary，距卡片上方 24、下方 4。用陈述式短语，结尾不加冒号。

**按钮。** 三种角色：primary（accent 填充 + 白字）、secondary（card 底 + 描边）、destructive（红字/红边，
仅确认操作使用红底）。一个视图只有一个 primary。行内操作按钮高 32，右对齐到控件列。按钮的 hover/normal
配色**不得**用 `tag` 承载（见 `AGENTS.md`）。

**开关。** 38×22，滑块 18；开启 = `accent`，关闭轨道 = `switch_off_track`。整行不可点击，只有开关可点击。
滑块沿用弹簧计算出的稳定时长，最低 180 ms；按压反馈为 220 ms，沿用关键帧默认曲线。这些组件专属值优先于
通用的快速时长和缓动 token。滑块只在其 2pt 内缩范围内跟随。

**滑杆。** 连续滑杆——**不带刻度**。已填充部分为 `accent`，滑块为白色 + 1px 描边。始终与右对齐的等宽数字
读数配对，且同一组内每一行的读数宽度一致。

**下拉框。** 宽 200，单行，溢出省略号，右侧 chevron。下拉面板 `radius-panel` + `med` elevation；条目使用
`radius-control`（8）与 `hover_bg` 填充。显示文本必须本地化且面向用户；如果原始值对开发者有意义而对用户无意义
（VID/PID、preset key），显示可读名称，把原始值移到 caption 行。

**输入框。** `field_bg` + `radius-control`，高 32，焦点用内嵌 accent 环表示。

**颜色选择器。** 带描边的色块 + 十六进制值（`caption`）。绝不用裸渐变图形。

**Tooltip。** `radius-panel` + `med` elevation，14pt 文字，悬停延时后瞬时出现、瞬时消失。
用于给出界面放不下的文本（被截断的 `caption`）的 tooltip 需按内容换行并自适应尺寸，上限见
`settings/tooltip.rs`；它对同一段文字绝不二次截断。固定尺寸的禁用提示与 toast 仍是单行。

**空态。** 居中的 `caption` 文字，`text_muted`；除非是首次运行界面（引导页），否则不配插图。

**按键显示。** 横向流（顶部/底部位置）每个键帽按内容定宽，至少 32pt，让单字符键帽也有接近 Command 修饰键帽的视觉宽度；组合键的按键并排放在一个纤薄托盘里，
连按计数内联拼接、不加空格（`A×99`）。纵向流（屏幕两侧位置）**每个键帽独立绘制，且共用一个固定
宽度**：组合键拆成每键一颗键帽（修饰键保留着色），没有分组托盘，因此轨道和面板不随按键内容变化。拖动条有透明的 48×20pt 命中区域（横排时旋转），大于可见的三个点；仍只限于拖动条，不让整个面板都可拖。竖排时命中区域距顶部边缘内缩 4pt，可见圆点靠命中区域外侧放置，与第一颗键帽留出间隔。
纵列时，连按计数放在键帽下方独立的小行并在 ×99 封顶；无论哪个方位，计数都用 muted 灰呈现——内联时紧贴键名，它是关于这次按压的元数据，不是键名的一部分。长键名在文案层面缩短（"Pg Dn"、下页，而不是
Page Down／下一页），使固定宽度容纳所有已发布语言的键名；更长的内容在键帽内部截断。

中性键帽的填充**按模式不同**；而作为浮动面板上承载文字的表面，它必须按**完整叠色链**测量——底图 → 霜面洗色（`window_bg` @`0xE9`）→ 键帽 → 文字——并在两个极端底图上都测，因为面板浮在任意内容之上（纯白与纯黑底图是两端；浅色面板在白底上落在 `(247,248,250)`，黑底上落在 `(225,226,228)`）：

| 模式 | 键帽填充 | 组合键外框 | 键帽 vs 面板（白底 / 黑底） | 键帽文字（白底 / 黑底） |
| --- | --- | --- | --- | --- |
| 浅色 | `field_bg`（内凹输入框表面）+ `card_border` | `card_bg` + `card_border` | 1.12:1 / 1.11:1 | 主 11.61 / 9.64，计数 4.62 / 3.83 |
| 深色 | `card_bg` @80% + `card_border` | `field_bg` + `card_border` | 1.04:1 / 1.19:1 | 主 12.67 / 13.46，计数 5.19 / 5.51 |

**键帽文字属于记录档**，不套用 §3.3 对 `text_primary` 的 12:1：那条下限针对的是 `window_bg` 与 `card_bg`，而键帽是面板自己绘制的**不透明键片**（见 §3.1 的键片取值），既不是这两个表面，也不随底图移动。已发布的蓝色键帽在最坏底图（浅色键帽压在深色内容上）就只测到 **主 8.48:1 / 计数 3.37:1**，因此这一档的下限记为**主文字 ≥8:1、计数 ≥3.25:1**，并由 `keystroke_display::panel` 的测试对两种键帽、两种模式、两个极端底图逐一断言。浅色中性键帽因此取 `field_bg` 压平到 `card_bg` 后的 `#F1F2F3`（不透明）：它同时满足「能承载文字」与「与面板有分界」——后者由键片自身的 1px 描边（`card_border`）承担，而不是靠让底图透出来。

深色保留更暗的 80% 卡片填充：改用同样的内凹表面后，那里只有主 9.77:1 / 计数 4.00:1（浅色文字需要深色键帽），而它在白底图上相对面板仅 1.04:1——这是记录值，深色键帽靠细边定义。

面板自身的表面是霜面洗色／玻璃 tint／`window_bg`，由调色板写入，因此**任何会改变主题的入口都必须重绘它**，而键帽每次渲染都重读调色板——表面若停留在旧主题就会出现"浅色键帽压在深色外壳上"。两个入口都要调用重绘：配置变更协调器（`ui_coordinator::apply_theme_and_locale_refresh`，负责显式切浅/深色与语言变更）与系统外观通知（`apply_system_appearance_refresh`，即 `theme = "auto"` 路径）。

## 10. 交互状态

每个自绘控件都要有全部六种状态，且都使用上文的 token，不得引入新颜色：

| 状态 | 处理 |
| --- | --- |
| normal | 基础 token |
| hover | `hover_bg` 填充（瞬时，无过渡） |
| pressed | 填充型控件用 ~85% 的 accent；描边型用 `hover_bg` + 轻微内陷 |
| selected | `selection_bg` 填充，或卡片/色块使用 accent 环 |
| open | `hover_bg` 填充、描边保持 idle；在同一位置就地展开的控件用 `hover_bg` + 轻微内陷。收起时必须清掉 open 表面：accent 环属于 focus，不属于“已展开” |
| disabled | `text_disabled`，控件填充 50% 不透明度，无 hover 反馈 |
| focus（键盘） | 内嵌 accent 环，2pt，在 `card_bg` 与 `window_bg` 上都清晰可见 |

点击热区至少 28×28；纯文字入口要靠内边距补足。hover 与选中**绝不改变布局**（不改变尺寸、不改变字重），
只改颜色。

## 11. 无障碍与本地化

### 11.1 始终成立的规则

- 对比度：见 §3.3。调色板任何改动后都要重新测量。
- Reduce Motion：见 §8，强制。
- 每个自绘控件都通过 AppKit 设置无障碍标签与角色，使 VoiceOver 读到的信息与像素一致；数值型控件要读出数值。
- 所有用户可见字符串都走 `t()` / `tf()` / `t_count()`，并在**全部** locale（`en`、`zh-Hans`、`zh-Hant`）
  都有键。缺键会把 key 本身渲染出来，屏幕上绝不允许出现。
- 标签和控件值里绝不出现配置键、枚举名、十六进制值、VID/PID 或内部 preset 标识符；用户自己的颜色值仅可作为颜色选择器的说明文字例外显示。
- 布局必须在伪本地化（`--pseudo-locale`）和长文本 fixture 下存活：不裁切、不重叠、用户需要读的标签不被截断。
- 文字缩放：用户可调字号永远不改变行的**结构**（不因为字号而让行多出一行）。

本节余下部分讲的是**语言容忍度**：一个字符串、一个盒子、一次按键，在「这个界面并不是用这门语言画出来的」
时候要付什么代价。§11.7 中标注为「已记录的缺口」的规则，是新代码和改动代码的准入门槛，不是把旧界面留在
原样的许可证。

### 11.2 换行、最小宽度与截断

每种书写系统都有一个「原子」，原子决定了盒子最窄能窄到哪。英文的原子是**词**：长度可变且不可断开，所以
盒子缩到最长那个词就停住（"Internationalization" 的 `min-content`）。CJK 的原子是**一个字**，同一个盒子
还能继续缩，字符串宽度接近字符数的线性函数。为前一种情况建立的设计系统里塞满了 `min-width`、`max-width`
和截断策略——没有一样是免费的，全都是为某一种书写系统打的补丁。

- **先换行，再考虑截断。** 让标签拿到它需要的行数，让行、列表、面板跟着长高。一行截断的德语和英语高度
  一模一样，因为它没有吸收多出来的长度，而是把它扔掉了——而高度是一行唯一能花的钱。
- **最小宽度要写成视觉宽度。** 写死的宽度必须是实测（或实测后取整）的 pt 值——菜单标题的 `72–280pt`、
  引导页状态列的 `160pt`——绝不是字符数。`ch` 是 `0` 的宽度、`ex` 是 x-height：两者都按拉丁字形定义，
  对 CJK 都是错的。
- **绝不让写死的宽度成为唯一托着标签的东西。** 当字符串就是唯一内容时，容器由实测的字符串推导，而不是
  反过来。
- **不要假设平台会按词的边界断开 CJK。** AppKit 公开的断行策略只有 `none`、`pushOut`（避免段落末行只剩
  一个孤词——「比例」的那一半）、`standard`，以及 `hangulWordPriority`——按词优先只有**韩文**有，中文和
  日文没有对应项；默认值还随控件类型不同（不可编辑/可选择的文本框用 `standard`，可编辑的用 `none`），而
  我们自己不设任何策略。所以没有任何东西保证中文的词不会被切开。我们能控制的是空间：字符串需要的宽度和
  行数——绝不用字符数估算决定切在哪里（见 §11.5）。切开一个词会改变读法的地方（短标签、标题），要看该
  locale 的实际渲染结果，不要假设。

**正文（§11.4）目前拿不到同样的处理。** 文本系统不会替我们做「词典」那一半：没有任何策略给中文、日文按词
优先，我们也没有设任何策略。但这不等于不可能。Apple 公开了能处理中日文的分词器（`CFStringTokenizer`、
`NLTokenizer`），而且两层 layout manager 的 delegate——TextKit 1 的
`layoutManager:shouldBreakLineByWordBeforeCharacterAtIndex:` 与 TextKit 2 的
`textLayoutManager:shouldBreakLineBeforeLocation:hyphenating:`——都会就每一个候选软换行点被询问是否放行，
所以分词器可以在不预先插入分隔符的前提下引导断点。它在这些视图里是否安全、是否划算尚未验证，因此这属于
一条已记录的缺口，而不是平台限制。

**在缺口关闭之前，用以下规则替代。** 正文保持容器的完整内容宽度，给正文用更窄的行宽需要理由而不是默认。
长中文段落要在评审时于**容器能取的每一个宽度**下真实渲染阅读，不要假设它没问题；今天每个表面只有一个
宽度——设置窗口用 min = max 钉死自身宽度，各面板是固定尺寸——但一旦某个容器变成可调宽度，它的整个宽度
区间都要进入这项检查。唯一已经在由我们自己断行的位置——剪贴板代码详情的软换行，优先取结构断点（逗号、
运算符、成员访问、空白），找不到才回退到任意字符边界——那是等宽代码的模型，不得复用到正文；正文需要的
是分词器而不是列数（见 §11.5）。

**已记录的偏离——固定的设置网格。** 严格按上面的规则，每一行设置都会因为最长的译文而长高。本应用选择保留
设置网格（行高 52、控件 32，见 §5）并改用截断，因为密度就是这个产品。这条偏离有边界：

- 默认只有 §9 允许清单里的内容可以截断；用户必须读的标签不可以；
- 任何截断都要给得出完整值——tooltip 或 caption 行；
- 某条本地化标签放不下时，修法是加宽列、缩短字符串或把细节挪走。绝不是缩小字号，也绝不是「它截断了，
  这就是策略」。

### 11.3 层级必须在内容语言里真实存在

拉丁字形把层级编码在字形内部：大小写免费给三层，然后是斜体、字重、小型大写、字距。CJK 只剩字重——还是
其中最弱的一个，因为给密集字形加粗是把字腔填满，而不是增加与周边空白的对比——而且完全没有大小写。一个
用大小写或斜体表达重要性的拉丁设计，翻到中文就没有东西可用了。

- 层级只用内容语言真正给得起的通道。§4 固定了这套集合：字号、字重、颜色。不许用大小写、斜体、小型大写，
  也不许让字距承载含义。
- 通道用尽时，优先用包围和间距，而不是再加一种颜色。一张看起来很挤的密集界面，通常是一张不得不拿颜色
  去买层级的界面。
- 绝不依赖某个「翻译后就消失」的通道单独承载含义。

### 11.4 密度花在外壳上，不花在正文里

CJK 单字信息更密，而密度买的是面积、不是时间：各语言的实测阅读速率是收敛的（约 39 bit/s），所以密集的
书写系统是「同样的意思占更小面积」，而不是更快。面积优势在外壳里真实存在，在正文里接近于零——因为汉字
的区分特征是**高空间频率的内部笔画**（未/末、己/已/巳），需要更多像素才能分辨。

- 密度优势花在外壳上：行标签、侧边栏条目、区块标题、键帽、卡片 caption、页脚文字。
- 不要把它存进正文。引导页正文、更新说明、错误说明和剪贴板详情保持完整字号和行高；中文能多放几个控件，
  不等于可以把一段话压紧。
- 12pt 是所有 locale 的下限，不只是拉丁语言的。见 §4。

### 11.5 方向、单位与输入

- **镜像的是关系，不是位置。** 编码顺序的东西要镜像——返回箭头、进度、滑杆、步骤流；表达约定或实物的
  东西不动——时钟、播放控件、对勾。数字完全不镜像：阿拉伯数字在 RTL 行内仍然是 LTR，于是一行里可能同时
  存在两个方向，光标移动和选区会悄悄改变含义。目前不发布 RTL locale，所以新界面使用逻辑 leading/trailing
  而不是写死左右；真到那一天，审计才不贵（见 §11.7）。
- **不要相信字符数。** 宽度来自实测或实测过的常量（§11.2）。同样的警惕要延伸到布局之外：绝不用字符数推导
  截断预算、校验上限、排序规则或搜索决策——`len()`、`toUpperCase()`、「这个字段放得下 24 个字符」都假设了
  它被设计时的那门语言。用户输入的长度限制按字素簇（grapheme cluster）计，而且计数只作为提示显示，绝不做
  无声截断。
- **给输入定价。** 八次拉丁按键产出八个字形；六次拼音按键产出一个候选菜单，用户必须把视线从句子移开去判断
  和挑选。所以：文字输入走平台文本系统，在输入法可能正在组字时绝不消费 Return；CJK 搜索直接在字符串上
  匹配，而不是先做一遍拉丁分词；任何界面都不得假设两种用户打字一样快。

### 11.6 语气

几何在每种语言里都有坐标，语气一个都没有。register、习语和节奏都活不下来，而且声音越强，丢得越多。

- **把字符串分成两类。** *功能性*字符串——标签、字段名、错误原因、设置项、权限状态、按钮标题——翻译，并
  遵守上面的规则；一翻译回来就变尴尬的字符串，在每种 locale 里**重写**，而不是翻译。
- **我们的声音靠措辞承载，不靠字体。** 所有界面都用系统字体绘制，所以翻译版不会悄悄丢掉某个显示字体缺失
  的 CJK 字面。不要为某条本地化字符串引入显示字体。
- 某个界面引入新的语气时，**把最响的字符串往返一遍**——`en → zh-Hans → en` 和 `en → zh-Hant → en`——
  并用你能判断的语言读回来的文本。中文是两个已发布的 locale 而不是一个，谁也不能代表谁：繁体**并不**一律
  更长（现有字符串里更长的不到十分之一，多数等长，也有一些更短），但一旦更长，往往是短 UI 串因为
  「應用程式」而翻倍——`应用` → `應用程式`、`立即重启` → `立即重新啟動`（这是个按钮标题）。要实测那个
  locale，不要假设哪一个会溢出。读不懂产品要发的那个语言，就感受不到到达了什么。

### 11.7 已记录的缺口

上面有三条规则并非每个既有界面都已满足。它们是新代码和改动代码的准入门槛；把旧界面留在原样需要一个理由，
而不是沉默。

- **逐 locale 的文本容纳。** 目前没有覆盖各界面的设置行标签、按钮标题、区块标题、caption、菜单项、浮窗卡片、
  页脚、剪贴板详情、按键显示、引导页与更新弹窗的完整容纳断言；§11.1 的伪本地化和长文本规则目前靠人眼检查。
  触碰这些表面时应补上对应断言；关闭本缺口需要在所有相关表面实际检查 `en`、`zh-Hans`、`zh-Hant` 与独立的
  伪本地化、长文本压力用例。
- **RTL。** 不发布 RTL locale，也没有任何东西被镜像；前瞻规则见 §11.5。
- **CJK 的词边界断行。** 平台既没有给中文、日文的按词优先，也没有接受断行器的参数。分词器
  （`CFStringTokenizer`、`NLTokenizer`）加 layout manager delegate 有可能补上，但它在这些视图里是否安全、
  是否划算尚未验证；在验证之前，我们能用的就是 §11.2 的逐宽度实读规则。

## 12. 新增 token 或取值

1. 优先复用现有 token。如果两个角色需要「略微不同」的颜色，说明角色划分错了——先修角色。
2. 确实需要新值时，加在 `src/theme.rs` 里同类旁边，给语义化命名，并同时补齐浅色与深色。
3. 任何新文字颜色都要实测对比度，并记录到上面的表里。
4. 同一次改动里更新本文。**不在本文里的取值等于不存在。**

AppKit 字重值在 `theme.rs` 中命名：regular `0.0`、semibold `0.3`、bold `0.4`。中档 elevation 常量对应上表的
`med`；切换器选中环内缩为 §6 定义的 3pt。

## 13. 评审清单

- [ ] 视图构造函数里没有新增字面量颜色、字号、圆角、间距或时长。
- [ ] 新增/修改的文字角色，在它可能出现的每个 surface 上都满足对比度下限。
- [ ] 每个新字符串在 `en`、`zh-Hans`、`zh-Hant` 都有键；屏幕上没有原始标识符。
- [ ] 控件都是单行；长值截断并能看到完整值。
- [ ] 每一条新增/改动的标签、按钮标题、区块标题在 `en`、`zh-Hans`、`zh-Hant` 下都不被截断，且没有任何
      不在 §9 允许清单里的内容被截断。
- [ ] 新增的宽度、截断预算或输入长度限制都不是由字符数推导出来的（见 §11.2、§11.5）。
- [ ] 新界面只用字号、字重、颜色建立层级——没有大小写、斜体或字距承载含义，也没有引入低于 12pt 的字号
      （见 §4、§11.3）。
- [ ] 新的文字输入把 Return 和未处理的命令交回平台文本系统，保证输入法能组字（见 §11.5）。
- [ ] 新增的「响」字符串已往返检查；语气类字符串是重写的，不是翻译的（见 §11.6）。
- [ ] 新增中文文案已在真实渲染里读过——短标签看每个支持的宽度，长段落看**容器能取的每一个宽度**——不假设
      平台会按词的边界断开（见 §11.2）。

- [ ] 动画只使用两档时长与标准曲线，并处理 Reduce Motion。
