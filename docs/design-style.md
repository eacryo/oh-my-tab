# 设计风格（Design Style）

这是 oh-my-tab 所有自绘界面的规范性文档。改动任何用户能看到的东西之前，先读这一份。英文版见
`docs/design-style-en.md`。

以下规则改编自 Meta 的 [Astryx](https://astryx.atmeta.com/docs/principles) 设计系统（语义 token、
每个维度只有一把尺子、按层级划分 surface、有目的的动效），以及本项目已经遵循的 macOS 惯例。当本文
与现有实现冲突时，**以本文为准，现有实现即为缺陷**。

本文 §11 的语言容忍度规则改编自 Rene Wang 的
[Build Interfaces That Survive Translation](https://rene.wang/essay/build-interfaces-that-survive-translation)。

偏离只有两种成立方式，且两种都要留下记录。要么是平台强制——AppKit 自己绘制的控件、系统提供的取值、
用户自己的内容——那就在代码旁写明原因；要么是项目有意放弃某条规则，那就在它适用的章节里写成
**已记录的偏离**，连同边界与理由（目前有两处：§3.3 第 2 条、§11.2）。没有记录的偏离，两种情况都算缺陷。

## 1. 适用范围

| 适用 | 不适用 |
| --- | --- |
| 设置窗口（侧边栏、页面、卡片、行、控件、底部按钮）；本应用生成的菜单项标题与 tooltip 文本 | 我们不绘制的原生 AppKit 外观：红绿灯、菜单排版与系统样式、系统面板 |
| 应用切换浮窗（卡片、标题、选中环、页脚、滚动条、关闭/取消入口） | 原样呈现的用户数据：窗口标题、应用名、剪贴板内容、文件路径 |
| 剪贴板选择器与详情面板 | 第三方窗口缩略图 |
| 引导页、更新提示、通知、tooltip | 未改造的 `NSAlert` / `NSPanel` 系统模板 |
| HUD：按键显示、指针定位、快捷操作反馈 | |

左列全部属于「外观」（chrome），必须使用下文的 token。右列属于「数据」：由布局规则摆放，但内容本身
绝不重新配色或改写。

## 2. 原则

1. **只用语义 token，调用点不写原始值。** 视图请求的是「卡片上的次要文字」，不是 `#73737A`。
2. **每个维度只有一把尺子。** 字号、间距、圆角各有一把固定的短梯子。不在梯子上的取值是 bug，不是特例。
3. **层级来自 surface 和描边，不来自阴影。** elevation 只表达「它浮在别的元素之上」。
4. **动效用来解释变化，绝不拖延操作。** 只做入场/退场，不做 hover 和高频状态。
5. **文字必须可读。** 对比度是量出来的，不是估出来的。
6. **可见即本地化、可见即可读。** 屏幕上不出现内部标识符或配置键；中文本地化界面里不写死英文。用户自己的颜色值只可作为颜色选择器的说明文字显示十六进制。
7. **只在一门语言里成立的规则不是规则。** 每个布局决定都要对照我们发布的所有语言（`en`、`zh-Hans`、`zh-Hant`）
   以及将来可能新增的语言来检查：宽度来自实测，绝不来自数字符（见 §11）。

### 3.2 Surface 层级

`window_bg` → `sidebar_bg` → `card_bg` → 弹出面板。每一层与它背后的那层在视觉上可区分，且任何一层不得
承担两种用途。窗口背景上一组成组的行就是一张卡片，不是另一种底色的窗口。

### 3.3 对比度下限

用**合成后**（带 alpha 混合后）的颜色，对元素实际所在的 surface 测量。

**表内数据的出处：旧测量 / 未重测。** 下表的每个比值都测于设计稿调色板迁移**之前**的调色板；
`window_bg`、`card_bg`、各文字灰与控制色都已在 §3.1 改变，而新 token 没有留下渲染像素的重测记录。
这些数字是历史记录，不是对当前取值的结论。可以由 token 精确计算（WCAG 公式，**不是**像素实测）的当前值：
accent `#2F6FED` 对 `card_bg` 4.32:1、对 `window_bg` 3.85:1；muted `#6B6862` 对 `window_bg` 4.70:1；
disabled `#7E7B83` 3.52:1；primary `#1D1C1A` 14.41:1；secondary `#4F4C48` 7.23:1。把任何一格当作当前值
引用之前，先重测。

**文字**

| 角色 | 下限 | 浅色实测（上一版调色板） | 深色实测（上一版调色板） |
| --- | --- | --- | --- |
| `text_primary` | 12:1 | 12.97:1（对 `window_bg`） | 15.63:1 |
| `text_secondary` | 7:1 | 8.19:1（对 `window_bg`） | 10.10:1 |
| `text_muted` | 4.5:1 | 5.16:1（对 `window_bg`）、5.53:1（对 `card_bg`） | 6.40:1 / 5.24:1 |
| `link_text` | 4.5:1 | 4.96:1（对 `window_bg`）、5.31:1（对 `card_bg`） | 6.01:1 / 4.92:1 |
| `link_text_hover` | 4.5:1 | 6.34:1（对 `window_bg`）、6.80:1（对 `card_bg`） | 7.28:1 / 5.96:1 |
| `text_disabled` | 3.5:1 | 2.58:1（对 `window_bg`）、2.76:1（对 `card_bg`） | 4.11:1 / 3.37:1 |

**硬性下限 3.5:1。** 上表的下限是每个角色设计要达成的**目标**。设计稿要求时，一个角色可以低于自己的目标，
但偏离必须连同计算出的比值写进本文档——任何文字或承载含义的图形在任一模式下都不得低于 3.5:1。
第 2 条的边界元素仍用自己的 1.2:1 规则。`accent_ink` 对 `accent` 就是这样一个已记录的偏离
（公式计算值，非像素实测）：浅色常态 **4.55:1**、浅色悬停 **5.83:1**、深色常态 **6.82:1**、深色悬停 **8.72:1**。
另有两处配对无法过线，做法是改 token 而不是登记例外：浅色 `text_disabled` 改取 `#7E7B83`
（对 `window_bg` 计算 **3.52:1**、对 `card_bg` **3.95:1**）；深色 `destructive` 改取 `#F53B30`，
白色 `accent_text` 在其上计算 **3.78:1**（它作为红色文字在深色表面上仍为 4.94:1 / 4.34:1）。

浮动面板键帽上的文字另属记录档（主文字 ≥8:1、计数 ≥3.5:1），因为那块表面会随底图移动——见 §9 按键显示。

`text_primary` 是整个调色板余量最小的一个。主文字色或 `window_bg` 变化时必须重测；不要为了「更好看」
而单独把它加深。

侧边栏选中项用设计稿的平坦导航底色（`nav_active_bg`）加专属墨色（`nav_active_ink`）：一对不透明配色，
按 3.5:1 硬性下限要求（公式计算值，非像素实测：浅色 **5.30:1**、深色 **4.92:1**）。链接色的文字
不适用此例外：一律使用 `link_text` / `link_text_hover`。

`scroll_indicator` 本身不承载含义，因此不受文字下限约束；但它必须在两种模式下都位于表面的可见侧：
比浅色面板更深、比深色面板更浅。固定用某一种模式的中性色，在另一种模式下就会消失（黑色滑块对深色
`window_bg` 只有 1.10:1）。

**非文字**

分两条，因为它们回答的是不同的问题。

1. **仅靠颜色承载状态 —— 下限 3:1。** 焦点环、选中环、状态点、错误/警告描边，以及任何「去掉颜色就
   失去含义」的指示。accent 为 `#2F6FED`：对 `card_bg` **4.32:1**，对 `window_bg` **3.85:1**——由当前
   token 按 WCAG 公式算出，不是渲染像素实测。它替换了 `#0A84FF`，后者在上一版灰阶上实测 3.65:1 / 3.40:1。
   新增状态指示必须先实测再上线。
2. **结构性边界 —— 下限 1.2:1，属于记录在案的偏离。** 卡片描边、控件描边、分隔线、开关轨道，
   承载的是填充、形状、位置和标签**已经**表达的信息。它们低于 WCAG 1.4.11 的 3:1 是有意为之：
   在 `card_bg` 上达到 3:1 需要 `rgba(0,0,0,.42)`（即 `#949494`），会像一条又重又不像原生控件的边框。
   在**上一版调色板**上实测（**旧测量 / 未重测**）：`card_border` 对 `card_bg` **1.25:1**；开关关闭态
   轨道 `#C7C7CC`（浅）**1.68:1**、`#636366`（深）**2.33:1**。这两个 token 现在都是半透明 wash（§3.1），
   这些数字已不再描述实发颜色。

   该偏离只在边界**不是控件的唯一标识**时成立。如果一个控件拿掉描边就认不出来——没有填充、没有
   标签、没有形状、旁边也没有图标——那它的描边必须做到 3:1，且应新增一个 `control_border` token，
   而不是去改 `card_border`。

开关是第 2 条的范例：开/关由滑块位置和 accent 填充表达，轨道颜色永远不是唯一信号。

新增 token 必须实测，不许目测。半透明颜色要按合成后的结果算，不能只看 alpha。

### 3.4 半透明

剪贴板选项菜单遵循 `clipboard-v2-1.html`，使用不透明的暖色回退表面，避免下层列表按钮清晰透出。
所属 token 为 `src/clipboard.rs` 中的 `POPOVER_*`、`popover_muted`、`popover_danger` 和
`popover_hover_bg`。此菜单有意采用设计稿的紧凑字号和行圆角，作为通用字号阶梯与同心圆角规则的例外。
数量与勾选独立成列，设置快捷键和清除提示靠右对齐；深色模式使用语义调色板。
设计稿尺寸可用 `sed -n '831,965p' /Users/ceres/Downloads/clipboard-v2-1.html` 重现，
实现 token 可用 `rg -n 'POPOVER_|fn popover_' src/clipboard.rs` 查看。

窗口和卡片背景可以半透明，以透出桌面形成玻璃感。设置页侧边栏使用不透明的 `sidebar_bg`，保证颜色稳定。设置窗口的标题栏条带在侧边栏那一侧是不透明的 `window_bg` 条，
其下一条 `separator` 发丝线（原型 `.settings-titlebar`：`background: var(--panel-solid); border-bottom: 1px solid var(--settings-divider)`）。
在详情栏那一侧条带不着色：根表面（`window_bg`）本身就是这条带，条带不会重复涂一遍。

**承载文字的表面必须足够不透明，保证上表在
最差背景下依然成立**。浮窗玻璃是例外：它是覆盖在任意内容之上的临时表面，其文字颜色必须按它能覆盖到的
最深和最浅背景来选。

浮动面板(切换器、剪贴板、按键显示)通过 `panel_material` 设置提供三种材质:

| 材质 | 表面 | 说明 |
| --- | --- | --- |
| `liquid-glass`(默认) | `NSGlassEffectView`,`glass_style`/`glass_tint` 子选项 | macOS < 26 退化为磨砂 |
| `frost` | `NSVisualEffectView`,behind-window,材质按模式钉死(浅色 `hudWindow` 13、深色 `ultraDark` 9),自身不铺任何表面 | 中性系统模糊;玻璃子选项不适用 |
| `opaque` | `window_bg` 填充,无模糊 | 系统开启「减弱透明度」时也是强制回退项 |

材质只改变面板内容背后的表面——文字颜色、间距、圆角与调色板完全遵循本文其余部分。

**磨砂（frost）在浅色模式下的亮度地板。** frost 是把桌面透过自身模糊出来的，所以它自己的表面跟着背景走：暗桌面上会掉进
中间亮度带，而浅色 `accent`（`#2F6FED`，WCAG 相对亮度 0.18）正落在这个带里——画在那种表面上的选中描边只有 ~1:1。因此浅色模式
会在 frost 之上、面板内容之下铺一层纱：设计稿的渐变（`glass::FROST_VEIL_STOPS`——0% 处 `rgba(255,255,255,.58)`、46% 处
`rgba(255,255,255,.33)`、100% 处 `rgba(255,249,241,.42)`，方向 CSS 148deg；数值抄自设计稿，未重新测量，
且渐变线按面板自身尺寸套用 CSS 规则（`glass::frost_veil_gradient_points`），所以在宽、窄面板上角度都成立）。分段线性平均 alpha
约 0.41、46% 处谷底 0.33，所以桌面平均保留约 59% 的可见对比度、谷底处保留 67%。`--glass-floor=<a>` 启动开关仍可换回
单 alpha 的纯白纱（默认 `glass::FROST_FLOOR_ALPHA` `0.4`）——它是测量仪器，渐变没法用一个数表示。作用域**只限 frost**——液态玻璃用自己那对
按模式实测的 tint，不透明材质没有背景可合成；暗色模式完全不动，因为它的材质本来就落在 accent 之下。

面板描边是沿面板自身圆角矩形的 1pt 内侧描边，token 随材质走：frost 用 `glass_rim`（浅色 50% 白 `#FFFFFF80`，深色与 `card_border` 同值），
`opaque` 与纯模糊的 `backdrop` 用 `card_border`（数值抄自设计稿，未重新测量）。frost 与 `opaque` 的面板描边是同一条视觉契约。**液态玻璃是例外**（`glass::install_panel_outline`）：系统材质本身已画方向性 rim（受光的上缘最亮、向内衰减），再叠一条均匀描边会把 rim 压平成画上去的线——玻璃与「带边框的矩形」的区别正在这里。共享的是**边缘**这个契约，不是实现手段。它画在材质之上的一层
装饰视图，而不是画在材质自身图层的 border 上：三个材质视图的结构不同（frost 带圆角 mask image，glass 会裁剪
自身），挂在任一材质上的 border 都会继承那套结构的行为。**视觉**契约是共享的，只有材质强制要求时才在实现上按
材质适配。

**承载对比度表的是「文字面」，不是材质。** 面板用两种方式之一满足下限，而这个选择正是三种材质能否互相
区分的分界：

**面板的表面就是它的材质，对比度由「墨」承担。** 没有任何面板在材质之上再画一层文字表面：那种表面只能盖住
面板的一部分，于是在它没盖到的地方就与材质成条（剪贴板面板浅色模式实测：空闲行 `#F3F4F6` 对旁边裸露材质
`#E2E2E4`，差 17 级，看起来像面板被切成条；深色模式约 75 级）。因此文字直接压在材质上，由**墨**守住下限：
半透明表面用动态系统标签色，表面本身就是 `window_bg` 的（`opaque`）用调色板 token。代价写在下面的浮窗档位里，
不藏着。

**材质本身提供模糊；两种外观的差别在 style 与 tint。** 实测方式：高频底图 + 面板覆盖区的高频能量，
与**同一帧内未覆盖的对照格**相除（只有这个基准经得起检验——未覆盖格读回 100% 源图；面板内无材质格 1.000；
普通半透明膜 0.43；`NSVisualEffectView(.hudWindow)` 0.19）：`NSGlassEffectView` 的每一种配置都把该能量压到
0.000–0.003——任何 variant、`regular`/`clear`、玻璃作窗口 contentView 或子视图、设与不设 tint、key 与非 key
面板、同进程与跨进程底图皆然。**因此模糊既不是旋钮，也不是区分维度。** 两种外观是：

| 外观 | `style` | tint |
| --- | --- | --- |
| `regular`（默认） | `.regular`（0） | `glass_tint`，逐字应用 |
| `clear` | `.clear`（1） | 同一 tint；令它更透的是 clear 这个 style |

`glass_tint` 是 `RRGGBBAA`，它的 alpha **就是**强度旋钮（没有单独的不透明度设置）。它作用于**浅色模式**；
深色模式改用固定深色 tint（`#1C1C1E99`）。这个分裂是实测结论而非偏好：面板没有文字表面时墨直接压在玻璃上，
而浅色 tint 在深色模式下让表面停在中灰，那里的 caption 墨最多只有 2.07:1；换成深色 tint 后同一格实测
**黑背景 9.93:1 / 白背景 6.00:1**（`scripts/e2e/panel-contrast.sh`）。两次"更聪明"的尝试都随版本发过，也都错了，记录在此：

- 按模式重新调明度：深色模式变紫——那里的 `palette.window_bg` 近黑，彩页自身的色相成了唯一活下来的东西。
- 把强度又乘了一次 255：alpha 塌成 20%，请求的纱从未真正生效。

默认值是 `eeeeee66`（浅中性色、40%）。除 `clear` 以外的任何值都渲染为 regular 玻璃，因此被下线的外观
（本 App 曾短暂提供名为 `system` 的第三档）会回退，而不会把表面变成空的。`glass_variant`、`--glass-blur`、
`--glass-saturation` 仍是开发开关，发行路径不碰私有 `_variant`——与 alt-tab-macos 的 `.regular` 玻璃同一选择。

**没有任何材质绘制文字底板；每一档按它的表面所能达到的档位验收。**

| --- | --- | --- |
| `liquid-glass` | 系统玻璃，渲染值远离 `window_bg`（深色模式落在中灰） | 动态系统标签色 |

| `opaque` | **就是** `window_bg` | 调色板 token（与它假设的表面完全一致） |

墨色能在其上达到 12:1 / 7:1。它们按下面浮窗那一档验收。

**渲染像素测量，以及它为什么还不是门禁。**手段是 `scripts/e2e/panel-contrast.sh` 与 `scripts/e2e/lib/png_stats.py`：
后者从文件本身推导缩放（固定像素区域在 1 倍屏上会量错条带）、在面板后钉一块纯黑或纯白窗口（让半透明表面有确定的背景）、
并比较两张截图，使**不同的像素就是字形像素**，而不是材质自身的色调噪声（深色磨砂单帧会给出十几个挤在 1.03–1.13:1 的
"墨"，那些是材质）。

审查与合成复现在这套比较里找出三个缺陷，且都会报出错的东西：为抗跨启动抖动而设到 10 个色调单位的差分阈值，会把处于
1.04:1 下限的 caption 整个丢掉、转而把它邻居的 11:1 当成该区域的答案；用**整区平均**当背景，会把 1.17:1 的局部对比度
报成 7.52:1；而只差材质的两个画面会被当成字形，从一个**完全没有文字**的区域里报出 1.26:1 的"墨"。现在测量改用 3 个色调
单位的阈值、对每个连通分量**取其周围像素的局部材质色**、并在差异像素超过区域三分之一时**拒绝**这组图而不是相信它；
三个反例都在 `png_stats.py --selftest` 里（共九例，引用本节任何数字前先跑它）。

  **不提供面向用户的颜色选择**：它是配置字段，而脱离调色板的色相会让 vibrancy 墨所依据的对比度表失效。

### 3.5 剪贴板面板 token（clipboard v2 稿）

## 4. 文字

共享文字使用以下档位；剪贴板 V2 的明确局部例外见 §3.5.1。

| 角色 | 字号 | 字重 | 颜色 | 说明 |
| --- | --- | --- | --- | --- |
| `page-title` | 26 | 700 | primary | 设置页标题，每页一个；字距 `-0.4` |
| `settings-title` | 12 | 500 | muted | 设置窗口标题栏条带中的窗口标题（原型 `.settings-title`） |
| `section-header` | 12 | 600 | secondary | 卡片上方的分组标题 |
| `row-label` | 14 | 400 | primary | 设置行标签、列表主文字 |
| `control` | 14 | 400 | primary | 下拉值、输入框文字、按钮标题、行内次要值 |
| `caption` | 12 | 400 | muted | 行说明、版本号、空态、脚注 |

- 内置字重只用 400 / 600 / 700。600 给区块标题，700 给标题。显式配置的 `fonts.*_weight` 是浮窗的高级外观偏好，予以保留；旧版 500 默认值会迁移为 semibold。
- 数字读数（滑杆值、条数、字节数）使用等宽数字（tabular figures），避免切换时抖动。
- 行高按字号相乘：12pt × 1.35 = 16.2pt，14pt × 1.4 = 19.6pt，标题字号 × 1.2。该规则只约束会折行的文本角色；单行文本不因此改变行盒。角色已定义行高时不得手工覆盖。
- 不要靠缩小字号来塞进控件。应该加宽容器或挪走内容（见 §9、§11.2）。
- **共享文字以 12pt 为下限（剪贴板 V2 的局部例外见 §3.5.1）。** 不要为徽标、键帽或密集标签引入更小的字号。汉字的区分特征是**高空间频率的内部笔画**
  （未/末、己/已/巳），能分辨所需的像素高于拉丁字形；对本调色板和这些表面，这条下限就落在 12pt。
- **层级只用字号、字重、颜色。** 绝不让大小写、斜体、小型大写或字距承载含义：中文没有大小写，合成斜体
  只会让密集字形更糟，而字重是这些信号里最弱的一个，因为加粗会把字腔填满，而不是增加与周边空白的对比。
  拉丁设计里想用大小写或斜体的地方，改用颜色和包围。`page-title` 的 `-0.4` 字距是视觉修正而非语义，也是
  全应用唯一允许的字距。
- About 页的版本号是 `caption`，不是一行数据：它属于页面副标题，不该占数值列。

### 4.1 浮窗文字

卡片标题、卡片应用名与页脚是全应用唯一可由用户缩放的文字。两个卡片 caption 共用
`layout.card_text_size`；页脚直接使用独立的 `fonts.status_bar_size` 设置。

| 角色 | 使用 `layout.card_text_size` | 有效字号 |
| --- | --- | --- |
| 卡片标题（`fonts.title_size`） | 是 | 缩放后 13…20pt |
| 卡片应用名（`fonts.app_name_size`） | 是 | 缩放后 13…20pt |
| 页脚（`fonts.status_bar_size`） | 否 | 配置值 0…20pt；**0 = 不显示页脚** |

- **卡片 caption 共用一个倍率。** 改动 `layout.card_text_size` 时标题和应用名同步缩放，相对大小不得漂移。
- **钳制作用于缩放后的结果。** 卡片 caption 的 `fonts.*_size` 是基数而非最终字号：以 12pt 为基数时
  卡片标题落在 `card_text_size` 上；应用名按比例缩放，两者都钳在 13…20pt。
- **页脚独立。** 字号直接使用 `fonts.status_bar_size`，经 0…20pt 配置范围校验；不随卡片 caption 缩放。
  设置页的控件是**底部标题栏文字大小**滑块，它的下限是 0 而不是共用的 13pt 文字下限：0 让整条页脚带消失
  （只有字号大于 0 时带子才存在），1…20 按配置值渲染，滑块按整数吸附。旧的 `layout.show_footer_title`
  开关已从界面移除；旧配置里它为 `false` 时，加载时会一次性迁移成字号 0。该字段只为旧配置文件和导出
  格式保留。
- **任一 caption 行的行高不超过所在卡片高度的 1/3。**
- **caption 只有一行。** 放不下就省略号截断，绝不换行，也绝不把缩略图挤出卡片。

Markdown 更新说明的一级标题使用 `sidebar-title` 粗体，二级标题使用 `control` semibold。浮窗基数字号、共享倍率和结果钳制已在 `theme.rs` 实现；显式字重覆盖仍视为用户偏好。

## 6. 圆角

| Token | 取值 | 用于 |
| --- | --- | --- |
| `radius-control` | 8 | 按钮、输入框、下拉框、色块、列表项高亮、开关轨道的内部几何 |
| `radius-legend-chip` | 5 | 只读快捷键图例中按键符号背后的底色块 |
| `legend-chip-text-pad-x` | 2 | 图例色块内文字两侧的留白；长键名由自己的色块撑开，而不是按字符拆成多个色块 |
| `radius-card` | 12 | 卡片、成组行容器、列表块、弹出项 |
| `radius-panel` | 18 | tooltip、下拉面板、HUD、通知卡片；剪贴板那两栏大面板画 32（`glass::CLIPBOARD_PANEL_RADIUS`），它是一张大 sheet 而不是小面板 |
| `radius-full` | 9999 | 胶囊：徽标、状态点、开关、滚动条滑块 |
| 品牌图标圆角 | 9 | 设置侧边栏 34pt 应用图标（原型 `.brand img { border-radius: 9px }`）；34pt 方块由自身高度派生出 9，8pt 控件圆角和面板圆角都不符合它的曲率 |
| 窗口圆角 | `radius-panel`（18） | 设置窗口本身（原型 `--radius-window`） |

**同心规则。** 有内边距的圆角容器，其内部元素的圆角为 `max(0, 外圆角 - 内边距)`。切换器的选中环是有意的例外：
外框仍在卡片外 `环内缩`（3pt），但圆角取**生效的卡片圆角本身**，让蓝环的角与卡片曲率一致、而不是平行外扩 3pt；
环半径仍由卡片半径派生，绝不手工指定。
切换器选中环的 `ring_inset` 为 3pt，且选中的是**整张卡片**——上面的标题行和窗口预览一起——所以切换器卡片区
底部另留 8pt 内缩（`theme::THUMB_BOTTOM_INSET`）来覆盖这 3pt 的外扩，否则卡片视口（止于底部标题栏）会把
最后一排的选中环裁掉。这 8pt 从标题栏自身高度中扣除，不占用卡片尺寸预算，`overlay` 里有编译期断言保证覆盖。

**纯图标**模式标的是同一个单位——整张卡片（图标 + 两行文字）——而色板**就是卡片的矩形**
（`theme::SELECTION_CARD_INSET` 为 `0`）。图标网格是卡片紧挨着排的，卡片自身的边界本来就是两个图标之间的中点
（各距 15pt），任何向外的内缩都会让色板离邻居的图标比离自己的更近，读起来像选错了卡。缩略图网格留了 14pt 间隙，
所以它的环可以外扩 `3pt`。两者填色都用 `selection_plate_bg`
（比列表行的 `selection_bg` 更重，因为要在半透明玻璃上托住一整个图标），描边 `2pt`
（`theme::SELECTION_RING_STROKE`）用 `accent`，圆角曲线用**超椭圆**（`CALayer.cornerCurve`）。纯图标色板的圆角是
它**自己的 token**（`theme::SELECTION_PLATE_RADIUS`，24pt），取自它所包图标的圆角，**不跟** `appearance.corner_radius`：
卡片本身不上色，没有第二条可见曲线需要与之平行，而那个设置是卡片圆角（上限 `radius-panel`）加面板圆角。缩略图那条环
仍是 `卡片圆角 + 环内缩`。

卡片高度严格等于内容所需（`theme::card_h`）：图标画布 + 两行文字 + 各内边距。过去是「固定基准高度 + 文字预留」，
结果卡片内部空出约 35pt——色板被挤到距标题只有 2pt，而底部空着一整条；那块空白也正是当初必须把命中区从卡片 frame
往里收的原因。现在卡片按内容定高，两种模式的命中区都是整张卡片，指针再也不会从一块什么都不画的区域里改选中。

小尺寸色块的圆角由自身高度推导，而不是套用 `radius-control`：`radius-control` 是按 32pt 控件设计的，
用在 19pt 色块上会占掉 42% 的高度，形状变成**胶囊**而不是「柔化过的矩形」。`radius-legend-chip`（5pt）
是 19pt 的 26%。`radius-full` 同样不适用于色块——胶囊是另一种形状，不是更圆的矩形。

## 6.1 图例不是控件

**图例**说明「按哪个键做什么」（`↵ 输入选中条目`）；**控件**是用户去操作的东西。两者刻意画得不一样，
这个差异不是装饰：

| | 图例 | 控件 |
| --- | --- | --- |
| 描边 | **无** | 1pt `card_border` |
| 底色 | 比 `field_bg` 更淡的一层浅色 | `field_bg` / `button_bg` |
| 指针状态 | 无 | hover、pressed、focus、disabled（§10） |
| 命中区域 | 无——它不可点 | ≥ 28×28 |

剪贴板底部的快捷键符号就是催生本节的情况。它们完全没有 target/action，但一次设计系统改造给它们加上了
`field_bg` **加 1pt 描边**——正是可点击控件的视觉契约。这是 UI 兑现不了的承诺：用户会学到「有描边的色块
可以点」，然后发现这些点不动。这套 accent 键帽色板（`keycap_accent_*`）在这里同样不适用——它的含义是
「该修饰键当前正被按下」，那是一个**实时状态**，而实时状态属于按键显示面板。

所以图例只保留「能被读懂」所需的东西：一层淡到不暗示交互的底色，它唯一的作用是把符号和它的说明绑定在
一起，让一行的多个图例仍然可扫读。它**不能**借用控件的描边、圆角阶或指针状态。

**一个图例色块对应一个按键，而不是一个字符。** 一个色块就是一个键：一个修饰键符号，或按键本身，
无论这个键叫什么名字。名字长于一个字符的键（`Page Down`、`Space`、`Return`）由**它自己**的色块
按实测文字宽度向两侧各加 `legend-chip-text-pad-x` 撑开，绝不按字符拆成多个色块。同一行色块之间
使用 `--spacing-0-5`（2pt）间距。由此有两条要求而非建议：色块段必须放得进它那一列留给它的空间
（放不下时整段移动，而不是压住相邻控件），空间不够时让位的是旁边的文字。

「尽可能淡」有下界，不能随意：底色必须仍然能与它所在的表面区分开，且在明暗两种模式下都成立。它以
wash 的方式施加（在浅色表面上压暗、在深色表面上提亮），而不是固定灰，因此一个取值在两种模式下都可用。

浮窗卡片圆角跟随 `appearance.corner_radius`，但最大为 `radius-panel`（18pt）。更大的配置值仍用于玻璃和窗口表面，
不会让切换器卡片变得过圆。窗口缩略图本身保持直角；关闭按钮和选中环从有效卡片半径派生，避免设置变化后残留过期几何。标题栏中的小应用图标使用 `radius-control`。

## 7. Elevation

四档。按**表面离页面多远**选，而不是按「阴影多重才好看」选。

| 档位 | 阴影 | 用途 |
| --- | --- | --- |
| `none` | —（仅描边） | 默认。行、卡片、行内提示、按钮 |
| `low` | `0 1px 2px rgba(0,0,0,.06)` | 需要与背景区分、但仍在文档流内的表面 |
| `med` | `0 4px 12px rgba(0,0,0,.10)` + 描边 | 浮在页面内容之上：popover、下拉菜单、tooltip |
| `high` | `0 12px 32px rgba(0,0,0,.18)` | 浮在整个界面之上：对话框、引导页、切换浮窗、剪贴板 picker 与详情面板 |

中档 elevation 在 `theme.rs` 中由一组共享的黑色阴影、不透明度、模糊半径和垂直偏移表示；下拉菜单和 tooltip
共用这些常量。高档同样由一组具名常量表示（`ELEVATION_HIGH_*`），三个浮动面板（切换浮窗、剪贴板 picker、详情面板）
使用它：它们浮在别的 app 内容之上，而不是浮在某个页面之上。按键显示 HUD 继续使用原生窗口阴影：它距可见边缘
只有 `PANEL_EDGE_MARGIN`（18pt），而高档阴影需要面板四周 64–76pt 的窗口外扩，窗口服务器随后会把外扩后的窗口
约束回可见区——实测这会把面板推移 26pt，并改变已保存位置的含义。给 HUD 单独做阴影属于它自己的放置决策
（记录在 `docs/review-backlog.md`），不是第二档 elevation。

**面板的 elevation 阴影只画在面板外侧。** 外扩存在的原因是窗口会裁掉超出自身 frame 的绘制，而它的尺寸来自实测，
不是由模糊半径推出来的：`radius + |offset|` 只是阴影核心的边界，不是它衰减到零的位置；只按半径外扩时，窗口最外
一圈仍残留 8 个色阶的阴影。实测要求的余量是 `ELEVATION_SHADOW_TAIL_ALLOWANCE`，
`scripts/e2e/panel-edge.sh` 就是复现该判定的命令（最外圈必须回到被钉住的背景色，且开关阴影时面板内部不得变化）。缩略图角标（全屏、最小化/隐藏）是承载白色符号的圆形 `badge_scrim` 圆片；圆片使用单独命名的
`symbol_shadow` 角色和共享几何常量；它是小尺寸对比辅助，不是表面 elevation。
该阴影的不透明度为 0.85、模糊半径为 2pt、垂直偏移为 −1pt。白色符号叠在纯白缩略图上的圆片之上实测对比度为
4.74:1，高于非文字指示器 3:1 的下限。

- 每个表面只用一档，绝不叠加阴影来「更浮」。
- 设置页里的卡片是 `none`：层级来自 `card_bg` + `card_border`。窗口内的卡片挂一层大范围柔光就是 bug，
  它暗示卡片浮在某个它并没有浮在之上的东西上面。
- 描边用 `card_border`，不要用阴影代替，也不要用更深的底色代替。
- 输入焦点使用内嵌 accent 环（2pt，见 §10），它不属于 elevation。卡片或缩略图块的选中态可以使用外侧 accent
  环；其外侧圆角按 §6 由卡片圆角和环内缩推导。

## 8. 动效

| Token | 取值 | 用途 |
| --- | --- | --- |
| `duration-fast` | 175 ms | 微交互；开关按压反馈使用组件专属时长 |
| `duration-medium` | 380 ms | 空间变化：面板开合、展开/收起、页面切换 |
| `ease-standard` | `cubic-bezier(0.24, 1, 0.4, 1)` | 除有明确理由外，所有动画 |
| 退场时长 | 入场时长的 0.75 倍，曲线相同 | 关闭面板、关闭对话框 |

规则：

- **上下文 UI 只做入场动画。** tooltip、hover 卡片、下拉菜单可以瞬间消失；面板、对话框、展开的行两个
  方向都做动画，且退场沿入场方向原路返回。
