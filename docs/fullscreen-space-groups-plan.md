# 全屏窗口与来源桌面归属组修改计划

- 日期：2026-10-03
- 状态：代码已实施并修复真实运行中发现的来源学习缺陷；`scripts/e2e/space-groups.sh` 已加入并在真实全屏转换上通过（两个方向）。来源未知全屏 Space 的隔离、多显示器、多桌面隔离仍只有 A1 纯测试覆盖，真实双桌面 A2 未运行。
- 项目：Oh My Tab
- 范围：窗口候选过滤、Space 归属跟踪、多显示器上下文、刷新一致性及验证

本文是修改计划。代码已实现独立归属模型、显示器拓扑与 Space 类型查询、WindowServer 成员/拓扑事件、保守候选过滤、来源未知降级、过期拓扑检查及转换期间禁止提交。

## 0. 实施结果与已验证范围

- 已实现：`src/space_groups.rs`（归属模型与来源状态机）、显示器拓扑与 Space 类型查询、1325/1326 等 WindowServer 事件、所有候选路径的统一归属过滤、刷新代数与转换期提交保护、`space_contexts` 等 e2e 诊断。
- 已修复真实缺陷：一次全屏转换会为该应用的辅助窗口发出属主无法解析的成员事件，旧实现按这些事件清除全部待确认配对，导致来源永远学不到；另外 1325 加入事件可能早于 SkyLight 把新 Space 标成全屏。现在只有确知的事件丢失（队列溢出）才清除待确认配对，属主未知只降低诊断标记；配对窗口由 1 秒放宽到 3 秒，配对在拓扑类型修正后仍会被重试。
- A2：新增 `scripts/e2e/space-groups.sh`（抢焦点场景，`--include-focus`）。它在真实系统上把窗口切进全屏，断言来源被确认、全屏 Space 与来源桌面共享候选，且回到普通桌面后仍能看到该全屏窗口。本机通过 8/8。
  - 该场景只在机器空闲时有效：它会真实切换前台应用与 Space，任何并发操作都会让上下文在断言途中改变；这种情况脚本会明确报告“上下文在测试途中移动”，而不是报成功能缺陷。
  - 断言只读 app 自己应用候选集后写下的帧（`refresh` / `refresh_context`），并且只接受本次启动进程（状态里有 `pid`）写出的帧，避免读到上一轮进程留在磁盘上的快照。
- 已复现但未修复的缺陷（不属于按住 Tab 那次改动）：回到普通桌面后，来源明确的全屏窗口有时不在候选里，而 `confirmed_fullscreen_origins` 仍为 1（来源没丢）。机制：`collect.rs` 的 AX 配对在**归属过滤之前**就把该窗口丢掉了 —— 当前桌面为普通桌面时，`kAXWindows` 不列出位于别的全屏 Space 的窗口，`published_map` 存在但不含该 cgwid，`recovered_map` 也没有（key/main 恢复只覆盖当前上下文的窗口），于是走 `continue`，成员过滤根本没机会通过已确认来源放行它。这正是 §7「窗口观察在归属过滤前采集」还没有完全落到的位置。
- 仍未运行的场景：真实**两个桌面**之间的跨桌面隔离（需要真的存在第二个桌面，本机未创建）；多显示器场景缺少设备。二者不计为通过，隔离分支目前只由 A1 纯测试覆盖。


## 1. 目标行为与候选范围

假设桌面一、桌面二各有普通窗口和一个进入全屏的窗口，预期如下：

| 当前切换器上下文 | 应显示 | 不应显示 |
| --- | --- | --- |
| 桌面一 | 桌面一普通窗口、来源为桌面一的全屏窗口 | 桌面二普通窗口、来源为桌面二的全屏窗口 |
| 桌面一的关联全屏 Space | 桌面一普通窗口、来源为桌面一的全屏窗口 | 桌面二的窗口 |
| 桌面二 | 桌面二普通窗口、来源为桌面二的全屏窗口 | 桌面一的窗口 |
| 来源未知的全屏 Space | 实际属于当前 Space 的窗口 | 猜测来源桌面的普通窗口及其他桌面的窗口 |

延续现有包含所有显示器当前上下文的候选范围：每块显示器分别计算允许的窗口，最后合并并按准确窗口身份去重。

| 每块显示器的当前上下文 | 允许显示 |
| --- | --- |
| 普通桌面 D | D 的普通窗口，以及来源明确为 D 的全屏窗口 |
| 来源明确为 D 的全屏 Space | D 的普通窗口，以及来源明确为 D 的全屏窗口 |
| 来源未知的全屏 Space F | 实际属于 F 的窗口 |
| 上下文或成员查询失败 | 保守降级，不使用猜测扩展归属组 |

### 1.1 用户开关对候选范围的加宽（2026-10-06 新增）

上表是**默认行为**。`windows.show_other_desktops` 是唯一被允许加宽它的用户开关，默认关闭；关闭时与上表逐字节一致。打开时的准入条件为:

```text
成员列表非空，且至少一个成员命中所接受的显示器拓扑中的受管 Space
（即：该 Space 出现在拓扑的 spaces 里，无论是否属于某显示器的当前归属组）
```

明确不做的事:空成员列表、或只命中拓扑未受管的 Space，仍然是拒绝 —— 这正是 orderOut/辅助表面呈现的形状，与「另一个桌面」不是一回事；旧版成员查询降级（含 `--space-membership-legacy`）不因该开关放宽，它区分不了其他桌面和离屏窗口。最小化开关仍然独立生效。窗口的实际成员与来源关联都不因该开关改写；激活目标始终是所选窗口的精确身份。

**AX 权威对本开关同样成立（2026-10-07 补充）**：准入放宽不等于「CG 列表里像窗口的都放行」。当某个应用的 `kAXWindows` 为空、而它的键/主窗口槽位仍然命名了该应用**某个**窗口时，AX 已经对这个应用的窗口集合给出了证据：此时一个既不在该答复里、也从未被 AX 识别过的 CG 窗口，是 AX 有意排除的次级表面（实测：微信 `3018` 主窗口旁边有一个 280×380、离屏、同标题的 `127`，从别的桌面看时它会变成第二张死卡 —— 没有 AX 元素，选中只会 `ax NO MATCH`），必须拒绝。判定放在「其他归属组例外」之前，因为这类应用正好落在 `ax_empty_pids` 里、否则会被例外先吃掉。为此保留一份「AX 曾经识别过的窗口」记忆（pid + 进程启动时间 + CGWindowID；窗口销毁与进程结束清理，并带销毁否决以免旧收集写回）。取舍与限制：真实存在的第二窗口若在**其桌面自本进程启动后从未被访问过**，在该桌面被访问一次之前不会显示（缺历史证据）；这是为了消灭死卡而接受的漏卡。若某应用的键/主槽位**也**为空，则进入第二条收窄（2026-10-07 补充）：**AX 对这个应用一个窗口都没命名时，它没有可切换的窗口可展示，其 CG 条目是面板**，一律拒绝——不论当前桌面还是跨桌面。实测：Stats 有一个 280×800、标题「Combined modules」、layer 0、**无父窗口**、离屏的菜单栏面板，它对 AX 完全不应答（`kAXWindows` 为空，`AXFocusedWindow`/`AXMainWindow` 均不支持），既会在别的桌面变成一张死卡，也会在自己桌面上变成一张卡；选中它没有任何反应。判定收敛为一个纯函数 `cg_only_pairing(published_any, recovered_any, query_failed)`：有 AX 证据 → 走「其他归属组例外」（仍需归属与形状门）；**AX 查询失败**（`ax_failed_pids`，即完全未知）→ 保留 CG 兜底；**AX 应答但一个窗口都没命名** → 拒绝。查询失败与「应答为空」是两种状态，不可混同；而且**查询失败只放行当前在屏的窗口**——没有 AX 答复就无法区分真实窗口与已关闭的菜单栏面板（实测：冻结 Stats 使其 AX 读超时，修复前会把可见的设置窗口和已关闭的 `Combined modules` 面板一起放行）。

理由:AX 的窗口列表按当前 Space 过滤，所以另一桌面的窗口没有 AX 元素（无标题、无最小化状态、无抬窗元素），只有 CGWindowList 的事实与 Space 成员可用。因此准入必须由成员证据单独承担，配对阶段需要一条仅在开关打开时生效、且只针对「其他归属组」窗口的受限例外（`WindowPairingSource::UnpublishedAx`）；当前归属组内仍然由 AX 决定一个窗口是否可切换。相关实现、参考实现的做法与实测见 [developer-notes.md](developer-notes.md) 的「其他桌面的窗口」；注意该项目曾把一次不可信的探针结论（「精确窗口前台切换不会移动 Space」）写进文档，已更正——该调用会切换，AltTab 与 BetterCmdTab 都依赖它。`thumbnail_workset` 只覆盖召唤时的抓图候选集；跨桌面归属证据由每趟收集暂存、只在该结果被接受时发布（预热等其他收集不会影响它），主题／显示器刷新与预热各自单独过滤，任务执行前还会按证据重查，而在途抓图无法收回，只能保证其帧不被渲染。

“来源”定义为窗口本次进入全屏前，可靠观察到的普通桌面。访问其他桌面、从其他桌面激活该全屏窗口，都不改变来源。

第一版将关联保存在内存中。应用启动时已经全屏的窗口默认来源未知；退出全屏后再次进入，可以重新学习来源。避免跨启动复用未经验证的旧身份。

选择全屏窗口后，macOS 跳到该窗口自己的全屏 Space 属于正常行为。归属组只控制候选范围，激活始终使用所选窗口的准确身份。

## 3. 增加独立的归属模型

新增 `src/space_groups.rs`，保存纯 Rust 数据与决策逻辑，避免将来源推断散落在窗口收集、事件处理和 UI 中。

| 数据 | 内容 |
| --- | --- |
| 显示器拓扑 | 显示器 UUID、当前 Space、所管理的 Space |
| Space 信息 | ID、可取得的 UUID、类型及显示器关系 |
| 窗口观察 | 准确身份、实际成员集合、全屏状态、观察版本 |
| 普通桌面基线 | 窗口进入转换前的可靠普通桌面关系 |
| 待确认转换 | 来源候选、目标全屏 Space、事件记录 |
| 已确认来源 | 来源显示器、普通桌面、全屏 Space、确认依据 |
| 有效性信息 | 拓扑版本、事件连续性、查询成功或未知状态 |

窗口身份使用 PID、进程启动时间和 CGWindowID；窗口生命周期变化时清理记录。不能以应用名、标题、窗口矩形或 MRU 代替身份。

实际成员关系与来源关联必须分开保存：

```text
actual_spaces       系统报告的实际成员关系
fullscreen_origin   根据历史证据建立的来源关联
```

来源关联仅用于扩大候选范围，不写回窗口实际成员集合。所有决策函数接受显式输入，便于无 GUI 的单元测试。

## 4. 扩展系统查询，保留显示器维度

修改 [window_collector/skylight.rs](../src/window_collector/skylight.rs)，让 `MembershipSnapshot` 保留显示器与当前 Space 的对应关系，以及 Space 类型和完整拓扑。

继续采用按 Space 批量枚举、再对遗漏窗口补查询的方式，并明确区分：

- 查询成功且有成员。
- 查询成功但成员为空。
- 查询失败或没有取得答案。

修改 [skylight.rs](../src/skylight.rs)，扩展已有 WindowServer iterator 查询，尽量一次批量取得 parent ID 和 Space 类型掩码。参考 AltTab 的 `SLSWindowIteratorGetSpaceTypeMask`，通过动态符号加载和返回值检查接入。

Space 类型优先使用经验证的拓扑类型字段或私有查询；窗口类型掩码作为辅助证据。尺寸铺满屏幕不参与来源推断。

查询前后核对拓扑，避免把转换前的显示器上下文与转换后的窗口成员拼成有效快照。共享 Spaces、镜像模式允许不同显示器引用同一个 Space，不能强制一对一。

桌面使用真实 Space ID；若能取得 UUID 则一起校验。“桌面一／二”的展示顺序不作为身份。

## 5. 扩展 WindowServer 事件，处理证据缺口

修改 [window_server.rs](../src/window_server.rs)，参考本机 AltTab 增加以下事件：

| 通知编号 | 本机 AltTab 对应含义 | 用途 |
| --- | --- | --- |
| 1325 / 1326 | 窗口加入／离开 Space | 更新成员变化证据 |
| 806 / 807 | 窗口移动／改变尺寸 | 触发实际状态查询 |
| 1329 / 1401 | 当前／活动 Space 改变 | 触发拓扑刷新与稳定期 |

成员事件单独解析 `(Space ID, Window ID)`。本机参考实现采用前 8 字节 Space ID 和随后 4 字节 Window ID；接入时检查载荷长度、零值及未知事件，不能继续使用现有读取前四字节窗口 ID 的通用路径。

回调只复制数据、记录到达时间并入队，不执行系统查询或 AppKit 操作。

事件队列调整：

- 成员加入／离开的顺序需要保留，不能按窗口简单合并。
- 移动／尺寸通知可合并成待查询标记。
- 销毁事件仍优先处理。
- 队列溢出或订阅失败设置可检测的证据不连续状态，并请求重新同步。
- 重新同步恢复实际成员关系，但不补造已经错过的全屏来源转换。

观察范围独立于当前候选列表、切换器显示状态和缩略图开关，覆盖已发现的相关窗口。订阅继续发送完整窗口集合，避免只发送新增项导致其他窗口失去观察。

私有通知含义及载荷来自本机 AltTab 的系统实测记录，实施时必须验证本机行为；失败时关闭相应学习能力，不恢复全屏全放行。

## 6. 实现来源状态机

| 状态 | 进入条件 | 后续处理 |
| --- | --- | --- |
| 普通窗口基线 | 稳定观察到唯一、可靠的普通桌面归属 | 保存真实基线 |
| 全屏转换待确认 | 同一窗口从普通桌面转向全屏 Space | 收集事件并等待稳定查询 |
| 全屏来源已确认 | 身份连续、来源唯一、目标成员与类型确认 | 保存来源关联 |
| 全屏来源未知 | 初次发现已全屏、证据缺失或冲突 | 不扩展到普通桌面 |
| 转换结束／身份失效 | 退出全屏、关闭、进程结束或拓扑失效 | 清理或重新建立基线 |

可靠来源的建立过程：

```text
W 在显示器 A 的普通桌面 D 上具有稳定成员关系
    + W 离开 D、加入全屏 Space F 的事件
    + 转换结束后的实际成员关系与类型确认
    → 记录 W / F 来源为 (A, D)
```

允许加入 F 先于离开 D，也允许相反顺序。使用转换前基线和完整转换记录判断，不能单靠最近离开的 Space。

不能以全屏 Space 的相邻桌面、显示器最近访问的普通桌面、应用名或相似标题推断来源。

遇到多个普通桌面成员、窗口身份替换、无法确认的跨显示器转换、事件缺失等情况，保持未知。退出全屏后以实际落点重新建立基线，不能假定回到原桌面。

一个桌面可关联多个全屏 Space。Split View 等一个全屏 Space 包含多个独立窗口时，只有相关窗口来源证据一致才建立整个 Space 的组关联；来源冲突或不足时按未知处理，保留其实际成员。

## 7. 统一所有候选过滤路径

修改 [window_collector/collect.rs](../src/window_collector/collect.rs)，替换当前全屏放行条件。

每块显示器分别计算允许的 Space 集合：

```text
当前为普通桌面 D：
    {D} + 来源已确认属于 D 的全屏 Spaces

当前为来源 D 的全屏 Space：
    {D} + 来源已确认属于 D 的全屏 Spaces

当前为未知来源全屏 Space F：
    {F}
```

窗口实际成员与允许集合相交，才通过归属检查。已有 AX 合法性、窗口类型、标题和隐藏设置等过滤继续执行。

打开 `windows.show_other_desktops` 时，上面的公式在末尾追加一项：成员命中受管 Space 但不在任何显示器的允许集合内的窗口也通过（§1.1）。判定顺序是「分类 → 选项」，即先把窗口分类为当前归属组 / 其他桌面 / 无证据，再套用最小化与其他桌面两个开关；这样定向刷新与全量收集必然给出同一个结论。配对阶段的关键点：`kAXWindows` 不列出其他桌面的窗口，所以「AX 有答复但没发布这个窗口」在开关打开、且成员证据指向其他归属组时走受限例外，而不是当作辅助表面丢弃；无证据时仍是丢弃。

全量收集、按 PID 收集、AX 补充窗口和恢复窗口使用同一决策函数。窗口观察在归属过滤前采集，避免被隐藏的窗口无法建立来源。

最小化设置仅控制是否显示最小化窗口，不能绕过归属检查。有实际成员时按成员判断；成员暂时不可取得时，仅使用身份仍有效、没有失效证据的已确认普通桌面基线。来源不足则隐藏，不能跨桌面全放行。

真实具有多个 Space 成员的窗口按实际集合判断，不能仅凭成员数量认定属于所有桌面。

移除 `LAST_CURRENT_SPACE_IS_FULLSCREEN` 对候选过滤的影响；全局全屏诊断字段改为每显示器上下文，避免聚合布尔值参与决策。

## 8. 接入刷新一致性检查

修改 [window_refresh.rs](../src/window_refresh.rs)，让每个刷新结果携带查询范围、上下文版本、事件连续性版本及本次观察结果。

后台任务只生成观察和拟议更新；主线程确认结果仍有效后，再提交归属记录与候选列表。过期任务不能污染长期来源缓存。

沿用 [space_transition.rs](../src/space_transition.rs) 的稳定期与代数检查。全局稳定期可继续用于调度，但不能代替按显示器保存的上下文。

Space 变化开始时标记上下文失效并刷新拓扑；稳定后确认成员与来源，再发布列表。快速连续切换、取消手势及重复通知都以最终实际快照收敛。

按 PID 刷新发现全局上下文或归属组变化时，升级为全量刷新，避免其他 PID 的旧候选残留。

切换器已打开时，上下文失效后不得提交旧候选；刷新期间暂停目标提交。恢复后按窗口身份保留选择，目标消失则重新选取有效候选。

## 9. 清理、降级与准确激活

在 [lib.rs](../src/lib.rs) 的应用终止路径，以及窗口销毁、显示器重配置和系统唤醒后的同步路径中，接入归属失效处理。

桌面重排只更新拓扑，不改变稳定身份对应的来源；桌面删除、Space 迁移、显示器断开和独立 Spaces 模式改变时重新验证关联。一次查询缺失不能直接判定窗口关闭。

降级策略：

| 可用能力 | 行为 |
| --- | --- |
| 成员查询可用，来源事件跟踪不可用 | 仅显示实际当前 Space 成员，不学习新的来源关联 |
| 成员查询也不可用 | 采用稳定、确实 onscreen 的保守路径，并记录降级原因 |
| 成员查询可用，`windows.show_other_desktops` 打开 | 按 §1.1 加宽准入；其他桌面的卡片标题取自 CG 窗口名（依赖屏幕录制权限，无权限时因标题为空而不显示）、最小化状态不可读、**不请求新抓图但继续显示缓存里已有的那一张**（`thumbnail_ready` 可断言）；激活先试应用前台切换、失败则用精确窗口前台切换兜底（参考 AltTab／BetterCmdTab；两者都不用 `CGSManagedDisplaySetCurrentSpace`，它跳过 Space 过渡机制会让目标 Space 失去菜单栏），目标进入当前桌面后再走同一条 AX 精确抬窗路径（含最小化恢复、迟到到达再补一次），并以 `other_desktop_raise`（目标身份 + generation + `onscreen` + `ax_matched`）发布结果 |
| 成员查询不可用，`windows.show_other_desktops` 打开 | 该开关不生效，仍是 onscreen 保守路径；`--e2e-state` 的 `space_filter` 会如实发布开关值与其他桌面准入数，便于断言这是降级而不是关闭 |

降级不宣称完整实现归属组，不恢复全屏全放行。历史成员关系可作为来源证据保留，但未经重新确认不能用于当前候选放行。

现有 `--space-membership-legacy` 强制路径改为保守策略；通过 `crate::dev_flags` 增加关闭来源事件跟踪等必要测试开关。运行时开关仅通过 argv 传入，不使用环境变量配置应用。

继续沿用 [overlay.rs](../src/overlay.rs) 的准确 `(pid, CGWindowID)` raise 和 AX 后备路径。归属信息不改变激活目标。

窗口身份在转换中变化时，先重新发现准确身份，不按同应用、相似标题或来源桌面替换目标。

## 10. 增加可断言的诊断信息

扩展 [e2e_state.rs](../src/e2e_state.rs)，输出当前已接受快照的以下信息：

- 每显示器当前 Space、类型及解析后的归属组。
- 每张候选卡的实际成员、来源关联及接受理由。
- 查询／事件版本、连续性及降级原因。
- 选中窗口、提交窗口及实际激活结果的身份。

测试模式保留必要的拒绝记录，便于断言其他桌面的窗口为何被排除。发布状态与实际显示列表一致，不能读取另一轮正在变化的全局数据。

## 11. 测试计划

### 11.1 A1：纯函数与集成断言

使用注入拓扑、窗口观察和事件序列的纯函数测试，覆盖以下场景：

| 类别 | 必须覆盖 |
| --- | --- |
| 基本行为 | 四种预期上下文；同桌面多个全屏窗口 |
| 多显示器 | 一屏普通、一屏全屏；两屏不同归属；共享／镜像 Spaces |
| 转换 | 两种加入／离开顺序；重复通知；取消及重叠转换 |
| 来源失效 | 启动已全屏；事件丢失；退出后换桌面再次全屏 |
| 生命周期 | 窗口销毁、进程身份变化、桌面删除／重排、显示器断开 |
| 查询一致性 | 失败与空答案；旧结果晚到；定向刷新遇到全局变化 |
| 其他窗口 | 最小化、隐藏、多 Space 成员、Split View 来源冲突 |
| 激活 | 提交身份等于所选身份；旧上下文候选不能提交 |

额外验证事件载荷解析、订阅失败、队列溢出及事件合并行为。移除或改写将全屏全放行视为预期行为的旧测试。

涉及真实 AppKit 视图树的现有适用 smoke runner，在 macOS 图形会话实际运行。无图形会话时记为未运行，不以 headless 测试代替。

### 11.2 A2：真实桌面与激活路径

新增 `scripts/e2e/space-groups.sh` 场景，通过 [run-all.sh](../scripts/e2e/run-all.sh) 运行。

使用带独特标题、记录准确窗口 ID 的测试窗口，安排在两个普通桌面并分别进入全屏。断言候选集合，同时从系统侧核对最终前台 PID、焦点窗口和目标 Space。

多显示器场景缺少设备时标记未运行，不能算通过。测试模式注入的数据不能代替真实系统场景验证。

另有 `scripts/e2e/space-desktops.sh`（同为抢焦点场景，默认跳过）覆盖 `windows.show_other_desktops` 的两态：关闭时另一桌面的窗口不得出现在候选里；打开时该窗口出现且标记 `other_desktop`、不进入 `thumbnail_workset`（抓图候选集），选中后提交身份、前台 PID、当前 Space 与目标窗口 `on_current_space` 四项对账，并要求 `other_desktop_raise` 记录 `onscreen`/`ax_matched`（匹配并提交抬窗，不等于系统侧已聚焦），另用独立 AX 读取核对最终焦点窗口。机器上没有第二个桌面时该场景打印 `NOT RUN` 并以 0 退出 —— 「未运行」不等于「通过」，报告时必须如实标注。它会在 trap 里恢复用户配置并重启应用。

实际改变桌面、全屏状态及前台焦点的 A2 执行，遵守 [AGENTS.md](../AGENTS.md) 的用户同意要求，声明抢焦点标记，并在结束后恢复测试前状态。

### 11.3 B：实际体验检查

观察切换器是否闪现其他桌面的卡片、连续切换是否出现旧候选、选择是否稳定，以及全屏目标是否准确激活。可断言的问题补充至 A 层测试或诊断状态，不以截图代替自动断言。

## 13. 实施顺序与交接门槛

按依赖顺序推进：

1. 归属数据模型与纯函数测试。
2. 显示器拓扑和 WindowServer 类型查询。
3. 事件解码、订阅与证据缺口检测。
4. 来源状态机及稳定快照确认。
5. 所有候选过滤路径与刷新一致性。
6. 生命周期清理、降级和提交保护。
7. 诊断信息、A2 场景及文档。
8. 完整检查、实际运行验证及交接。

交接前运行：

```sh
cargo fmt
cargo check
cargo clippy
cargo test
scripts/dev-restart.sh --no-onboarding
scripts/e2e/run-all.sh
```

获得抢焦点测试同意后，通过 `scripts/e2e/run-all.sh --include-focus` 执行相关 A2 场景。没有授权或硬件不足的场景明确列为未运行。

需要检查响应速度时，使用 `scripts/dev-restart.sh --opt --no-onboarding`。报告脚本打印的 timestamp-based build-version。若脚本报告 `restart FAILED`，检查最新日志、诊断并重试。

所有开关通过脚本 argv 传入。新增时间参数集中定义在所属模块，遵守项目的 UI 与动画约束。实现过程中保留无关用户改动，不自动 stage、commit 或 push。

完成标准：

- 四种上下文与多显示器规则均有断言。
- 未知来源不猜测，不扩展至普通桌面。
- 所有收集路径使用相同归属规则。
- 最小化和 fallback 不绕过 Space 过滤。
- 过期刷新不污染归属缓存或候选列表。
- 选择全屏窗口后准确激活所选窗口。
- 构建、自动化和实际运行验证分别报告，未运行场景明确列出。
